# Границы этапа 09

Текущий base predicate API принимает include-композицию до skip/take, поэтому сортировка Sequence/Version и ограниченная выборка ExpiresAtUtc/Id не требуют custom query. ById допустим для глобального DialogRecord.Id; для локальных turn/step IDs используются полные родительские predicates.

Чистое чтение не зависит от изменяющего UoW. После проверки владельца оно собирает независимые JSON-снимки всей истории и активного compact. Например, compact ThroughTurnSequence=1 не удаляет tool output или failed model report первого обращения из результата чтения. Предыдущие compact доступны адаптером версий и не изменяются.

RecordStaging<TEntity> — инфраструктурная адаптация base CRUD без прикладных бизнес-решений. Это не application repository port, сценарный UoW или сохранение. Этап 10 должен выполнять проверки и Domain mutations до staging и сохранять через общий scope; публичные DTO хранения не разрешают обход доменных инвариантов.

До чтения детей фиксируются primitive owner/incarnation/revision/metadata, а после детей повторно читается root. Удаление, смена владельца, жизни или версии дают NotFound/Forbidden/Conflict без snapshot и без retry. Например, пересоздание того же ID другим владельцем не позволяет отдать новую историю старому владельцу. Orphan items/steps и незавершённый принятый compact отклоняются явно. Изменяемая ссылка на persistence DTO не используется как исходная версия сравнения.

Несколько последовательных read-запросов и повторная root-проверка не объявляются транзакционно согласованным снимком при конкурентной записи. DTO/token не разрешает позднюю запись: atomic write guards остаются этапу 10. Неожиданные ошибки и отмена распространяются; повреждённый JSON/формат не заменяется пустыми данными. Реальные БД, relational enforcement и concurrency исключены из проверок этапа. Реализован и принят; запрещённые проверки пропущены: 71 passed / 0 failed / 0 skipped, 37 новых тестов. CLI validation не выполнена, change не архивирован.
