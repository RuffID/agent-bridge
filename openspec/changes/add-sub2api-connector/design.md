## Подтверждённая текущая граница

Первая версия согласована без обязательного compact. Режим03.03.01 закрывает её обязательный объём03.03 в изолированных границах; совместимость окна и реализация03.03.02–03.03.06 сохранены отдельной отложенной работой. T05 остаётся blocked для compact и не блокирует приёмку первой версии. Это изменение объёма не завершает остальные проверки; отдельно порученный04 completed после PostgreSQL evidence,05.01–05.02 проверены локально; отложенный compact и live05.03 не начинались.

Причина выбора — отсутствие нового достаточного основания исключить потерю покрытой истории после server recovery. Например, turns1–10 остаются в полном input вместе с turn11; при превышении бюджета guard или сервер возвращает явный отказ, а история остаётся сохранной. Длина диалога ограничена доступным входным бюджетом. Альтернатива с обязательным compact сохранила бы блокировку первой версии; best-effort потеря покрытой истории и генерация вместо compact не принимаются. Нормативная граница — в [delta spec](specs/agent-runtime/spec.md).

Текущее решение03.03: sub2api AutomaticCompactionEnabled=false, прежние IModelGateway имеют default true. ContextCompactor после validation/builder/counter возвращает Disabled без compact dispatch/save, сохраняя полный PreparedRequest/окно/token. AgentRunner продолжает separate generation guard: threshold не ограничивает размер input; known window и explicit unknown policy сохраняются. Ручной/force compact возвращает Unsupported. Ошибки executed compact не становятся fallback generation. Это аддитивный default interface member и новое последнее значение enum, не provenance/persistence04; полная бинарная acceptance остаётся на05.

Основание — не сам model mapping, а конкретный путь: после принятия opaque окна покрытые turns отсутствуют в следующем request; HTTP invalid_encrypted_content recovery может удалить compaction целиком и успешно обработать оставшийся хвост. Current local sub2api0.2.20 сохраняет этот путь. [Разбор и условия включения](../../../Documentation/Plans/sub2api-connector-2026-11-06-(in-progress)/03-sub2api/03.03-compaction.md), [current evidence отдельно от прежних hashes](../../../Documentation/Plans/sub2api-connector-2026-11-06-(in-progress)/03-sub2api/contract-source-evidence.json). Совместимость конкретных разных моделей не объявляется опровергнутой. Independently verified actual identity не является самостоятельным условием, если пригодность окна доказывается existing контрактом; requested echo и единичный success недостаточны. Safe mode не закрывает T05 и не разрешает best-effort compact/text summary.

## Проекты и зависимости

AgentBridge.Sub2Api размещён отдельным csproj в adapters, зависит от ядра и HttpClientLibrary. CodexLb остаётся самостоятельным адаптером. AgentBridge.Responses — папка единых internal исходников writers/controls/output/SSE framing, подключённых Compile/Link в оба адаптера; отдельная protocol DLL/public framework не требуется. Gateway/lifecycle/typed errors/continuation не переносились. Старые public CodexLb types/constructors и assembly identity сохраняются в прежней сборке.

Integration собирает один connector bundle. Существующий AddAgentBridge(configuration, httpClientFactory) и отсутствие нового выбора сохраняют codex-lb. AddAgentBridgeSub2ApiConnector либо AddAgentBridgeCodexLbConnector вызывается до facade; повтор того же выбора идемпотентен. Новый раздел Sub2Api не требует фиктивного CodexLb. Смена выбора после facade и неоднозначность отклоняются; custom service overrides сохраняются. Пример: приложение вызывает AddAgentBridgeSub2ApiConnector(), затем прежний facade с AgentBridge/Database/Sub2Api; startup options/scopes и чтение доступных ID работают. При явной новой budget policy settings сохраняет null окно; generation отправляет полный request и читает JSON/SSE без continuation; compact остаётся Unsupported из-за T05.

Legacy facade может сохранять статическую ссылку на CodexLb. Поэтому отдельные csproj не объявляются доказательством DLL-поставки только одного коннектора. Сначала проверяется совместимость старого приложения, затем фиксируется реальный closure.

## Ключи и ресурсы

Для AgentBridge ключ sub2api — Bearer credential gateway. Он отличается от OpenAI upstream API key и OAuth подписки. Индивидуальный/общий источник, scoped lifetime и pinning на run следуют existing контрактам; ошибка ключа не разрешает fallback.

IConfiguration используется для Options binding в регистрации. HttpClient/handlers/logger принадлежат приложению. Регистрация не выполняет HTTP/SQL, не запускает host и не строит временный ServiceProvider. Diagnostics использует existing safe pipeline: код/статус/operation IDs без ключей, raw bodies/headers, reasoning и произвольного server text.

## Протокол и конкретный сценарий

План первой версии: HTTP JSON/SSE с полным рабочим контекстом, без исходящего previous_response_id и без нового compact. Пример: turn1 получает function_call, приложение сохраняет durable checkpoint, выполняет tool один раз, отправляет полный input с парой function_call/function_call_output, получает terminal response. На turn2 передаётся полный подготовленный контекст с предыдущими turns и текущим input через отдельный guard; при превышении бюджета возвращается явная ошибка без обрезания и повтора.

В проверенном sub2api HTTP previous_response_id исключает OpenAI OAuth upstream accounts. Полная история без anchor — выбранное направление; live reasoning/encrypted_content и tools остаются приёмкой первой версии, compact→generation — отдельной отложенной работой. Если матрица или live-проверка обнаружит несовместимость, реализация не подменяет стратегию скрытым retry или WebSocket.

Обычный /v1/models может не подтверждать нужные metadata. Codex manifest имеет другой envelope/поля; преобразование бюджета и effort должно опираться на проверенный контракт. context_window и input_context_window не приравниваются автоматически. Неподтверждённые возможности дают Unsupported.

Текущая реализация03 сохраняет ordinary ID path и выбирает existing manifest только при ServerValidationWithUnknownWindow. Manifest вызывается по /backend-api/codex/models с нормализацией конечного /v1 и без client_version; upstream Codex-версию выбирает sub2api. Читаются exact slug/effort/API-доступность как объявления сервера, без вывода о budget или metadata runtime pool. [Клиентские ограничения](../../../Documentation/Plans/sub2api-connector-2026-11-06-(in-progress)/03-sub2api/contract-blockers.md) отделяют реализованные settings/generation от неподтверждённого compact. Gateway отклоняет incoming continuation/unsupported controls до factory. Actual generation выполняет один POST и читает JSON/SSE по Content-Type; compact блокируется отдельно до HTTP. Этап04 проверен отдельно; это не live OAuth evidence.

Продолжение03 уточнило actual owning paths: ordinary/passthrough mapping различаются, но transport normalization OAuth stream/store/SSE→JSON сама по себе не теряет canonical. Обратимые tool/ID формы требуют проверки конкретных пар; text truncation hooks в текущем source — no-op. Shared normalizer удаляет непустой reasoning.content, ordinary invalid-encrypted recovery и cross-mode failover могут удалить encrypted items. Compact может изменить модель до первого send. Response.model может быть requested echo; internal raw-model observation в admin usage не служит публичным доказательством upstream identity.

[Серверное предложение](../../../Documentation/Plans/sub2api-connector-2026-11-06-(in-progress)/03-sub2api/server-contract-proposal.md) **отклонено**: sub2api не дорабатывается. Versioned opt-in/pool revision/single-attempt enforcement/new metadata не являются зависимостью или новым требованием к серверу. Запрет client retry не запрещает все server retries; изменения тела и совместимость opaque оцениваются отдельно по actual existing paths.

[Текущий путь адаптации](../../../Documentation/Plans/sub2api-connector-2026-11-06-(in-progress)/03-sub2api/contract-blockers.md) сохраняет существующие routes и композицию/HttpClientLibrary. Unknown budget не превращается в выдуманное число, response.model echo — в independently verified model; unsupported compact не подменяется generation. Existing ServerValidation требует известное окно; отдельная ServerValidationWithUnknownWindow меняет клиентский бюджет и его snapshot. Canonical гарантия относится к клиентской границе, server reasoning normalization/recovery допустимы без обещания upstream сохранности. Shared SSE accumulator сохраняет codex-lb continuation через wrapper; sub2api continuation всегда null. Локальное происхождение04.01 описано ниже отдельно от бюджета. T01/T05 открыты;04.02 completed после isolated runner/restart/recovery и5 PostgreSQL cases. Runtime старого consumer и live OAuth не следуют из этих проверок.

## Сохранённые диалоги

Сохранность истории и успешное продолжение через другой шлюз — разные свойства. Не удалять историю, не сбрасывать opaque items, не переписывать настройки/выбор модели ради прохождения запроса. Connector identity учитывается при проверке compact и непокрытых outputs, даже когда model ID совпадает.

Поддержка ранее сохранённых диалогов обоих коннекторов отменена. 04.01 использует один новый JSON wrapper отчёта с полями envelope (исходный JSON как строка или null), connector и binding. Canonical envelope/output и transport continuation не дополняются локальными полями. Старый raw EnvelopeJson/null отклоняется явно; reader v1, version dispatch и backfill отсутствуют. Существующий ResponseFormatVersion=1 остаётся физическим ограничением схемы, не выбирает reader. Отдельный budget snapshot v1/v2 не меняется.

ModelConnectorProvenance связывает connector/dialog/owner/agent/endpoint/key; TurnId исключён для следующего turn, ключ не сохраняется. Это доверенные локальные metadata, не авторизация и не upstream identity. IModelContextGateway — добавочная capability встроенных gateways; старые публичные сигнатуры сохранены. Runtime проверяет отдельно active compact, каждый непокрытый model output и residual input/tools, затем маркирует подготовленный request. Одинаковая модель и IContextModelCompatibility не обходят guard. Новый opaque provider/input без происхождения отвергается; обычный текст допустим. Direct gateway проверяет marker до HTTP; отдельный ContextCompactor проверяет источники до новой маркировки. Metadata не попадает в wire body или логи. Например, родное compact-окно sub2api не разрешает непокрытый reasoning codex-lb при том же model ID.

04 completed: isolated actual facade/runner/Sub2Api/storage без fake gateway и5 PostgreSQL cases04.02.04 подтверждают новый DI/DbContext, полный payload/provenance, fencing, explicit recovery и no-replay. Физический сетевой сбой и рестарт сервера не моделировались. Подробности в [результатах04](../../../Documentation/Plans/sub2api-connector-2026-11-06-(in-progress)/04-dialog-state/results.md). На05.01–05.02 прошли1707 isolated cases, strict validation,23 external builds,42 Metadata/23 ABI/7 Windows binary tests; [результаты05](../../../Documentation/Plans/sub2api-connector-2026-11-06-(in-progress)/05-acceptance/results.md).05.03 не начат.

## Ввод и доказательства
