# Контекст этапа 11

Раздельные сборки позволяют хранить независимые provider snapshots при одном runtime DbContext. Сборки зависят от общего EF-адаптера; обратной ProjectReference нет. Приложение должно поставлять выбранную migrations DLL, когда выполняет обслуживание схемы.

По ревью runtime и factories используют AgentBridgeMigrationsHistory.TABLE_NAME (__AgentBridgeMigrationsHistory), чтобы не смешивать ledger с __EFMigrationsHistory подключающего приложения. Это служебная таблица EF вне пяти mapped сущностей; она не добавляется в generated initial migration/snapshot. После правки три builds 0 warnings/errors, 6 адресных factory/history/snapshot tests passed, 0 failed/skipped; широкий набор не повторялся. Реальные provider history repositories разрешены только как metadata, DB/SQL методы не вызваны. Generated файлы неизменны, повторной генерации нет, model diff пуст.

CLI workflow использует dotnet-ef/Design 10.0.11, SQLite/EF runtime 10.0.11 и согласованный Npgsql provider 10.0.3. Tools для Package Manager Console не требуется. Фабрики задают синтетические параметры и отклоняют forwarded arguments; секреты приложения не читаются.

Например, target/startup проекта SQLite совпадают, а factory возвращает AgentBridgeDbContext с SQLite и сборкой AgentBridge.Persistence.Migrations.Sqlite. PostgreSQL использует аналогичный отдельный target/startup. Создание модели не исполняет Up/Down и не открывает connection.

Исходная модель содержит ровно пять собственных таблиц: Dialogs, DialogTurns, CanonicalItems, ModelSteps, DialogContexts. Owner index не требуется текущему чтению по ID; нужен expiry/Id index. Составные keys/FK, cascade, UTC ticks, BINARY/C и fixed-field/concurrency metadata сохраняются. Локальный Domain lifetime не заменяет persisted incarnation.

Пользователь разрешил обе команды генерации; они выполнены однократно в порядке SQLite → PostgreSQL с pinned dotnet-ef 10.0.11, --no-build и временным BaseOutputPath, восстановленным в finally. Migration IDs: 20261003155233_InitialAgentBridgeSchema и 20261003155235_InitialAgentBridgeSchema. Migration/designer находятся в Migrations; snapshots штатно созданы в AgentBridge/Persistence/Migrations/Sqlite/Migrations и AgentBridge/Persistence/Migrations/PostgreSql/Migrations внутри своих проектов. Неожиданный относительно предварительного прогноза namespace-based путь не исправлялся вручную: штатная discovery обнаруживает оба snapshots.

Up/Down, designer и snapshot проверены совместно: пять таблиц, четыре cascade FK, три индекса, 20 checks, payload и provider collation/ticks. Up/Down не исполнялись. Snapshot/designer model bodies идентичны; IMigrationsModelDiffer не обнаруживает differences с текущей model. После генерации до history isolation три builds 0 warnings/errors; 114 tests passed, 0 failed, 0 skipped (6 новых за этап). Этап реализован и принят; запрещённые проверки пропущены. Реальные locking, relational enforcement, restart, backup и применение схемы не проверяются этим этапом. CLI validation отсутствует, change не архивирован.
