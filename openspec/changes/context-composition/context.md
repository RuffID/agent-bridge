# Контекст композиции

Сборщик готовит данные для последующего обращения и подсчёта этапа 17, но не вызывает модель, tokenizer или compact. Полная история и рабочее окно имеют разные обязанности: окно замещает только принятый terminal prefix, хвост сохраняется целиком.

Инструкции остаются в отдельном поле `ModelRequest.Instructions`. Вход содержит вклады приложения, Items активного контекста, Items обращений после ThroughTurnSequence и ещё не сохранённый input. Envelope и continuation остаются metadata, а StoredModelStep не является вторым источником уже сохранённых output.

Приложение выбирает разрешённые провайдеры и их порядок, отвечает за права и срок их DI scope. Каждый вызов ожидается до следующего; общий EF scope нельзя использовать параллельно. Ошибка провайдера не разрешает пустой fallback.

Пользователь согласовал любые canonical вклады с исходными ролями: авторизация принадлежит провайдеру. Известная function_call без результата, в том числе после обрыва SSE с partial arguments, препятствует подготовке запроса. Сборщик проверяет call_id на полной последовательности, не изменяет arguments/output и не раскрывает opaque state ради поиска скрытых вызовов. Это отказ композиции, а не удаление частичного состояния из хранения или изменение lifecycle отчёта.

Public ContextBuilder получает явно выбранную последовательность провайдеров и уже прочитанный DialogSnapshot. ApplicationCallContext.AgentId передаётся провайдерам без изменения. Snapshot не содержит AgentId: persisted agent ownership не вводится, adapter продолжает проверять agent binding continuation при отправке. ModelRequest на входе содержит только ещё не сохранённые items; builder не пытается угадать повторы по тексту или идентификаторам JSON.

call_id не является глобальным уникальным ключом всей истории: две отдельные пары с одним ID допустимы. Каждый известный output закрывает ровно один предшествующий ещё не закрытый call. Это согласовано с actual codex-lb `app/core/openai/requests.py`, где `_compact_matching_tool_call_index` и `_compact_reconciled_tool_call_indices` сопоставляют списки unmatched calls. Первоначальная дополнительная проверка уникальности снята после статического ревью до первого test run; регрессии покрывают повторные закрытые/открытые пары между turns и источниками. Соседние исходники только прочитаны после их AGENTS, не изменены и не исполнялись.

Пример: окно покрывает обращения 1–2. Запрос сохраняет полный opaque output этого окна, все Items обращения 3, включая вызов функции и результат, затем новое сообщение. При prefix=0 все обращения остаются в хвосте. Состояние read DTO не является разрешением записи или транзакционным снимком; поздняя запись отдельно проверяет исходные incarnation/revision и фиксированный срок.
