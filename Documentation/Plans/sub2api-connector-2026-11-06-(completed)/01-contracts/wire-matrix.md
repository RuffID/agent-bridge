Первая версия не обещает поддержку остальных платформ и Responses→Chat Completions мостов.

S5 имеет cache TTL 60 секунд / stale TTL 5 минут, pinned/scheduler/local-generation ветки, ETag/304; client_version участвует в upstream запросе. AgentBridge не должен объединять каталоги разных ключей или принимать 304 без своего принятого тела. На первом чтении без If-None-Match нужен полноценный body. Даже совпавший ID в manifest и обычном каталоге не доказывает одинаковую семантику account capabilities.

**T01 остаётся открытым.** В текущих исходниках не найден достаточный публичный источник входного бюджета. До подтверждения server contract запуск с таким каталогом должен честно давать Unsupported. Этап01 фиксирует препятствие; он не разрешает обход ModelSelectionValidator, ручную таблицу возможностей или правку sub2api. Если подтверждение потребует нового публичного поля/настройки либо изменения соседней библиотеки, нужно отдельно определить расширение.

## Ограничения гарантий самого шлюза

S7 уже имеет account failover. S8 в обычной HTTP-ветке после invalid_encrypted_content может удалить encrypted reasoning fields и повторить запрос; используется также lineage очистка. S11 имеет собственные условия failover/retry. S12 resolveOpenAICompactFallbackModel может выбрать compact-only mapping либо Gateway.OpenAICompactModel и повторить compact при определённых отказах. Эти преобразования происходят внутри sub2api, без нового HTTP-вызова со стороны AgentBridge.

Следовательно, требование проекта «коннектор не делает скрытый retry/смену модели/ключа» проверяемо на клиентской границе; оно не доказывает неизменность upstream account/model/opaque input. **T05** требует установить выбранный server profile, фактические mapping/retry настройки и наблюдаемые response metadata. Если строгая гарантия сохранения opaque/модели недостижима на этом профиле, приёмка блокируется; нельзя молча считать успешный ответ доказательством соблюдения требования. Соседний репозиторий в этапе01 не меняется.

По чтению A1 достаточно существующей границы HttpClientLibrary для request headers, JSON и owned SSE streams; отсутствие нужного API библиотеки не обнаружено. Это не подтверждение runtime совместимости и не разрешение обходить её собственным HttpClient.SendAsync. Извлечение shared code относится только к02.02 после отдельных разрешённых проверок.
