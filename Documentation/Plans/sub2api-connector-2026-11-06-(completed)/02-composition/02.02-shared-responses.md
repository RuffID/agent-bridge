# 02.02. Повторное использование общего протокола

Статус: **completed** (общие механизмы и legacy regression). Зависимости: 02.01.

[Этап](main.md) · [Главный план](../main.md)

## Конкретный результат

Общие JSON/SSE механизмы используются обоими коннекторами без копии всего CodexLb gateway.

## Затрагиваемые части и объём

CodexLb/Responses readers/writers/SSE, HttpClientLibrary pipeline; при обоснованной необходимости новый adapters/AgentBridge.Responses с собственным csproj/AGENTS.md.

По матрице01.01 выделить только реально совпадающие функции протокола. Gateway, options, каталог и identity коннектора оставить раздельными. Решение о shared assembly оформить по фактическим границам; не создавать общий фреймворк ради одного похожего метода. Сохранить прежние public CodexLb types/constructors в их сборке, при необходимости делегировать общей реализации. Не менять canonical payload и старый continuation format.

## Проверки

Существующие JSON/SSE/compact/error/disposal тесты codex-lb на actual HttpClientLibrary и fake handlers. Проверить callback ordering, partial stream, malformed UTF-8/JSON, primary+cleanup failures, caller/deadline и resource ownership.

## Критерии готовности

Legacy поведение и бинарная поверхность01.02 сохранены. Общий код не зависит от Sub2Api/CodexLb settings и не содержит автоматической смены шлюза/ключа. Важные безопасные диагностические события проверяются через existing logger pipeline, без raw body/headers.

## Фактический результат

В adapters/AgentBridge.Responses выделены ResponseRequestWriter/ResponseRequestBody, CompactRequestWriter, NestedControlsValidator, SseEventReader и CanonicalOutputReader. Это единые internal исходники Compile/Link в обоих адаптерах, без новой protocol DLL/public API и без зависимости от settings/identity коннектора. По матрице01 совпадают JSON формы canonical input/tools/reasoning и compact, вложенные controls, массив output и SSE framing. Server-side преобразования не являются гарантиями этих helpers.

CodexLb сохранил собственные gateway, lifecycle readers, ResponseSseState, typed safe errors и continuation mapper: они связаны с его состоянием/identity, их преждевременное обобщение не требуется. Catalog/options/URL semantics/public constructors и assembly ownership не менялись. Writer получает прежний previousResponseId явно от CodexLb; будущий Sub2Api должен передавать null и полный рабочий input. Legacy continuation format не менялся.

414 existing codex-lb tests прошли через actual HttpClientLibrary/fake handlers: JSON/SSE/compact/errors, callback ordering, partial/EOF, UTF-8/JSON, caller/deadline, cleanup и безопасная диагностика/ownership. Три дополнительных cases проверяют общие механизмы, скомпилированные внутри Sub2Api, через actual library: full canonical input/tools/opaque, null anchor, compact JSON, BOM/multiline/EOF и owned stream. Они не вызывают Sub2Api generation и не доказывают OAuth-совместимость.

Сохранность baseline и PE comparison трёх затронутых/связанных legacy assemblies проверены отдельными четырьмя tests. Старый transport probe компилируется без изменения исходника, его методы не исполняются. Это source-linked compile и semantic API check, не external binary consumer и не resolution frozen TypeRef/MemberRef/MethodSpec.
