## Конкретный результат

Existing AgentRunner проходит sub2api end-to-end path с durable ordering и pinned access/settings.

## Затрагиваемые части и объём

AgentRunner, ContextBuilder, ContextCompactor, run lifecycle/tool journal; existing persistence/hosting tests и Sub2Api fixtures.

Проверить несколько turns через public DI и инструменты с полным контекстом без нового Sub2Api compact; затем новый DI root и дальнейшую генерацию из сохранённого рабочего контекста. Проверить отключённый automatic compact, отдельный budget guard и явный Unsupported ручного/force compact до factory/HTTP; успешный Sub2Api compact/T05 не входят в приёмку первой версии. Не заменять это прямым вызовом gateway. Сохранить owner/expiry, fencing, settings snapshot, checkpoints и no-replay при unknown commit. Adapter identity не меняется от config reload в середине run. Не переписывать DB/UoW ради транспорта.

## Проверки

Удаление/expiry в ожидании HTTP, смена settings после начала run, HTTP partial/error после tool execution, отмена, неизвестный writer outcome, stale lease, restart recovery-required и cleanup errors. Isolated fake store отдельно от реального persistence restart; реальные provider tests запускать только в разрешённых границах.

## Критерии готовности

Sub2Api не обходит established durable guards и бизнес-инструмент не повторяется из-за отказа модели. Непроверенная реальная БД явно остаётся отдельной категорией evidence, а не скрывается под isolated restart.

## Фактический результат

Изолированная часть содержит16 сценариев в tests/AgentBridge.Persistence.EfCore.Tests/Sub2Api. Public facade создаёт настоящий Sub2Api gateway/settings/catalog/access, AgentRunner и production persistence reader/UoW; doubles ограничены app ports, локальным HttpMessageHandler и existing base repositories. В ней host и соединения с БД отсутствуют. Актуальный isolated persistence-набор после дополнительных JSON regressions: 510 passed, failed/errors/skipped0; compile-check без warnings/errors. Исправлено только устаревшее ожидание URL manifest в pinned-run test: exact /backend-api/codex/models и два /v1/responses вместо общего префикса /v1/.

Restart04.02.02 по-прежнему означает сериализованные DTO. Отдельная04.02.04 теперь подтверждена пятью настоящими PostgreSQL cases: новый facade/DbContext root после disposal, полный новый payload/provenance, потеря acknowledgement после actual start/outcome commit, lease/fence и explicit append-only recovery без replay. Original SQL rows сохраняются. Это не рестарт сервера PostgreSQL/ОС и не физический сетевой сбой. Подробности и команды — в [результатах04](results.md). Production DB/UoW/runner/transport в этой проверке не менялись. Этап04 completed;05 и отложенный compact не начинались.
