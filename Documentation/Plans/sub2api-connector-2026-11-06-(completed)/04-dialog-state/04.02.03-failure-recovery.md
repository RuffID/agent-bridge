# 04.02.03. Отказы и recovery

Статус: **completed** в изолированных границах. Зависимости: 04.02.01–02.

## Результат и объём

Actual Sub2Api/runner и production lifecycle/checkpoint/recovery/UoW защищают уже выполненное business action при отказах модели и неопределённой записи. Только тесты, без изменения production DB/UoW.

## Проверки и критерии

HTTP rejection, incomplete terminal SSE, SSE EOF с partial output и caller cancellation после tool не вызывают retry/replay. Поздние reports не восстанавливают удалённый или истёкший диалог и не обходят fence. Active-run delete сначала получает existing delete_active_run; после истечения lease и явного fence удаление выполняется настоящим deletion port.

Unknown commit acknowledgement моделируется после applied Started либо Succeeded commit; новый экземпляр не начинает generation/tools автоматически. Отмена handler оставляет Unknown и RecoveryRequired после serialized restart; только explicit recovery добавляет effective result, не переписывая исходные записи и не повторяя действие. Cleanup failure после commit не выдаётся за успех и не вызывает retry.

## Фактический результат

11 cases Sub2ApiRunFailureTests/Sub2ApiRunRecoveryTests прошли, failed/skipped0. Fake transaction не подтверждает SQL isolation или настоящий сетевой разрыв commit. HTTP response content освобождается; live server drain не проверялся. Existing safe outcome logging не заменяет durable journal.
