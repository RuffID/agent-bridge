# 06 — Доменное состояние и срок истечения диалога

Статус: **Реализован и принят; запрещённые проверки пропущены**. Зависимости: **01, 02**.

## Цель

Представить владение диалогом, упорядоченные обращения, состояние контекста и фиксированный срок от создания.

## Задачи

- [x] Спроектировать идентичность диалога и владение пользователем независимо от идентификаторов Telegram или WPF.
- [x] Зафиксировать время создания и настроенный срок истечения при создании диалога.
- [x] Представить статус обращения, версии контекста и потерю актуальности после удаления/очистки.
- [x] Сохранить доменные инварианты внутри доменных типов, не ослабляя их ради контрактов хранения.
- [x] Убедиться, что сообщения и compact не продлевают срок истечения.

## Проверка и завершение

Проверить нестандартный срок из конфигурации, доступ после истечения и переходы версий контекста с управляемым временем. Этап завершён, когда доменное поведение не зависит от EF- и HTTP-типов.

Источник: [поведение хранения](<../../Business logic/04-storage-and-retention.md>).

## Реализованный результат

`Domain/Dialogs/` содержит `Dialog`, `DialogId`, `DialogOwnerId`, `DialogTurn`, `DialogTurnStatus`, `DialogContextState`, `DialogStateVersion`, `DialogMutationResult`. Корень создаёт и изменяет агрегат; дочерние снимки неизменяемы, наружу выдаются read-only оболочки. Domain зависит только от BCL; EF, HTTP, options, прикладные порты и storage concurrency не добавлены. Локальные границы: `Domain/AGENTS.md`.

Настроенный срок сначала вычисляется существующим `DialogRetentionOptions.CalculateExpiresAtUtc`, затем фиксируется фабрикой `Dialog.Create`. Все операции получают явный UTC; `nowUtc >= ExpiresAtUtc` запрещает новое обращение и поздний результат. Запись с временем раньше последнего изменения отклоняется до мутации. Доменное удаление разрешено также после истечения и очищает обращения/контексты без возможности восстановления поздним результатом.

Каждое успешное изменение увеличивает `Revision`; снимок старой версии не принимается. Случайная идентичность жизни привязана к объекту в памяти: другой объект даже с тем же ID отклоняет снимок. Это **не persistent concurrency token** и не проверка restart/rehydration. На этапах 07–10 необходимы сохраняемая идентичность жизни и атомарная проверка существования/версии после повторной загрузки; они здесь не реализованы.

Пользователь прямо согласовал `ThroughTurnSequence` как префикс обращений с конечным статусом, включая 0. Выполняющееся обращение и незавершённая дыра внутри префикса отклоняются. Повторный compact может покрывать тот же префикс, не удаляя историю. Это чистые метаданные обращений; cutoff канонических элементов Responses, сохранение payload и composition/compact относятся к этапам 14–18. Настройки модели/effort и отправка сообщения не реализованы; фиксированный срок не имеет API продления.

Фактический API и пример: [доменное состояние](<../../Technical documentation/08-dialog-domain-state.md>).
