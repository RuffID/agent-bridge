# 02.01. Выбор коннектора в DI

Статус: **completed** (подготовка композиции, без операций этапа03). Зависимости: 01.02.

[Этап](main.md) · [Главный план](../main.md)

## Конкретный результат

Новая явная регистрация sub2api при неизменном старом AddAgentBridge.

## Затрагиваемые части и объём

AgentBridge.Integration, новый AgentBridge.Sub2Api/Configuration, existing IntegrationRegistrationTests; ближайшие AGENTS.md и solution.

Спроектировать и реализовать единый выбор connector bundle: gateway/catalog/access/settings и свои options. Без явного выбора оставить codex-lb. Sub2Api mode не требует фиктивного раздела CodexLb. Повтор идентичного выбора идемпотентен; conflicting selection, смена коннектора после facade и несовместимые аргументы отклоняются до I/O. Сохранить действующие app overrides и отдельно определить совместимость custom ports, не запрещая legacy overrides автоматически.

## Проверки

DI tests: старое подключение, явные оба варианта по отдельности, отсутствие ненужной конфигурации, конфликт, repeated calls, custom services, scope validation. Registration не строит ServiceProvider, не вызывает HTTP factory и не разрешает scoped источники из root.

## Критерии готовности

Существующий consumer не меняет вызовы. Новый выбирает один коннектор в composition root. HttpClient, handlers и logger остаются app-owned; generation не получает скрытый fallback на второй коннектор.

## Фактический результат

В Integration добавлены AddAgentBridgeSub2ApiConnector и AddAgentBridgeCodexLbConnector перед прежним AddAgentBridge. Выбор фиксирует один bundle; отсутствие выбора сохраняет codex-lb. Повтор выбора до/после facade — no-op, конфликт (включая смену неявного default после facade) и новые config/factory references отклоняются без I/O. Известные встроенные CodexLb ports нельзя смешать с выбранным Sub2Api перед facade; фабричные custom ports считаются контрактами приложения и сохраняются. Direct AddCodexLb* не стали selector API и сохраняют добавляющую семантику.

AgentBridge.Sub2Api имеет собственные options/enum и safe binding Sub2Api без фиктивного CodexLb. Shared/Individual presence validation не разрешает scoped источник из root. Gateway/catalog/access/settings — scoped подготовленная граница с явным Unsupported, без HTTP factory, fallback и фиктивного успеха. Реальная обработка ключей и server capabilities остаётся этапу03.

20 новых DI cases и 56 прежних IntegrationRegistrationTests прошли без host/сети/БД; build0 warnings/errors. Custom overrides, PostConfigure, scopes, direct registrations, фабрики и безопасные ошибки options проверены. [Команды/evidence/ограничения](results.md). Владение HTTP/handlers/logger остаётся у приложения. Внешний consumer/runtime и old→new ABI здесь не объявляются принятыми.
