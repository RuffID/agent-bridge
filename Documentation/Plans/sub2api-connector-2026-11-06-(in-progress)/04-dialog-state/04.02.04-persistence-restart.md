# 04.02.04. Реальный persistence restart

Статус: **completed**. Зависимости: 04.02.01–03.

[04.02](04.02-restart-and-recovery.md) · [Результаты](results.md)

## Результат и объём

Отдельно подтвердить restart/recovery сохранённого Sub2Api диалога на настоящем поддерживаемом persistence provider. Это выделенная проверка исходной границы04.02, а не расширение поведения продукта.

Использовать existing Integration fixtures/временные ресурсы и новый DI/context экземпляр; public runner и actual Sub2Api должны работать с локальным HTTP handler. Соседние библиотеки и рабочие БД не менять. Миграция прежних диалогов не требуется.

## Проверки и критерии

После записи, disposal и нового DI root восстановить полный новый payload/provenance, продолжить новый turn и проверить отсутствие повторов tools. Различить подтверждённые результаты настоящего provider и injected acknowledgement failure; проверить established fencing/recovery barriers. Не подменять DB restart JSON-копией или EF metadata.

## Фактический результат и ограничение

2026-11-08 по отдельному поручению выполнены пять PostgreSQL cases в Integration/Sub2Api/Sub2ApiPersistenceRestartTests. Использованы existing DatabaseIntegrationFixture/IntegrationDatabase, отдельные БД контейнера postgres:18 и настоящий maintenance/EFCoreLibrary/persistence pipeline. Facade вызывает тот же public AgentRunner.RunAsync с registered RunOptions, что и консоль. HTTP остаётся local handler, business handler — тестовый; внешние подключения и host отсутствуют.

JSON и SSE проходят запись инструмента и полного opaque payload/provenance, disposal facade root, новый DI root и новый turn без replay. Started виден отдельному DbContext до handler. Сопоставляются original SQL rows DialogTurns/CanonicalItems/ModelSteps и полный восстановленный turn; reasoning с неизвестным полем, первый вопрос/ответ, результат инструмента и новый input попадают в следующую generation.

Отдельно после настоящего commit Started либо Succeeded вводится потеря acknowledgement. Сохраняются primary failure и реальная ошибка rollback завершённой NpgsqlTransaction; Active запрещает новый run, живой lease запрещает fence. При expiry equality на управляемом server TimeProvider fence увеличивает epoch и запрещает старый Renew. Succeeded продолжает с сохранённым output; Started остаётся Unknown и требует явного AcknowledgedUnknown. Никакого автоматического business replay или объявления NotStarted нет.

Отмена внутри уже начатого handler сохраняет Unknown и RecoveryRequired. После нового root run отклоняется без HTTP; explicit append-only recovery сохраняется в БД, читается третьим root по RecoveryId и разрешает только новый turn. Original SQL rows не меняются, повтор handler отсутствует.

Итог: 5 passed, 0 failed/errors/skipped; 9,941 с финального прогона. Повторный isolated persistence-набор: 510 passed, 0 failed/errors/skipped. Compile-check без warnings/errors. Fixture очистил БД/контейнер/каталоги; последующий docker ps -a и собственный temp root пусты. Точные команды и границы — в [результатах04](results.md).

Restart здесь означает пересоздание приложения/DI/DbContext над настоящей PostgreSQL, без рестарта сервера БД или ОС. Acknowledgement failure и interruption вводятся управляемо, без физического обрыва сети или kill процесса. SQLite/MSSQL, backup/restore, live OAuth и поставка не проверяются этим набором. 04.02 и этап04 завершены в согласованном объёме;05 не начат, compact/T05 не изменены.
