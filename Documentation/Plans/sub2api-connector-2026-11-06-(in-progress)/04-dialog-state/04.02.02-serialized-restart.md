## Результат и объём

Новое приложение с новым DI root и новыми committed DTO продолжает сохранённый диалог через actual public runner/Sub2Api. Старый экземпляр disposed перед основным продолжением.

## Проверки и критерии

Все committed таблицы копируются через JSON; проверяются equality сериализованного состояния и отсутствие shared списков/root объектов. Actual reader восстанавливает новый wrapper с provenance; следующий запрос содержит opaque, tool call/result и прежнюю историю. Инструмент повторно не выполняется. Чужой ключ в новом контейнере даёт Conflict до Begin/generation без изменения истории; чтение manifest при этом допустимо.

## Фактический результат

Два cases Sub2ApiRunRestartTests прошли, failed/skipped0. Проверен новый формат, без reader старых диалогов и version dispatch. Это сериализованный restart isolated storage, не reconnect/restart настоящей БД; последняя проверка остаётся в04.02.04.
