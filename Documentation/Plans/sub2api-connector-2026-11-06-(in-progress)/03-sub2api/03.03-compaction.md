## Затрагиваемые части и объём

Sub2Api compact transport/reader, ContextCompactor и IDialogContextWriter existing path; Sub2Api tests.

Подключить подтверждённый compact endpoint выбранного sub2api-направления и корректный body. При отсутствии поддержки вернуть явный Unsupported; не имитировать compact обычной генерацией. Сохранить canonical compact items и metadata, Completed-only acceptance, save-before-activation, покрываемый terminal prefix и непокрытый хвост. Не урезать историю до лимита провайдера молча.

## Проверки

Completed/Failed/Canceled/malformed compact, capabilities unavailable, fresh expiry, late response, второй compact, tools на границе окна, отказ сохранения, непрозрачные items, timeout/disposal. Логи не называют compact принятым до успешного writer результата; ключи и содержимое не выводятся.

## Критерии готовности

Compact можно принять существующим портом без изменения вызывающего бизнес-кода. Неподдержанный compact остаётся явным ограничением и блокирует заявление полной поддержки обязательного сценария.

## Фактический результат

Автоматический compact sub2api отключён явно через IModelGateway.AutomaticCompactionEnabled=false. Default interface property true сохраняет прежние реализации и codex-lb. ContextCompactor после existing validation/builder/counter возвращает Disabled с полным PreparedRequest, прежним окном/token и нулём compact-проходов; writer не вызывается. Separate generation guard остаётся обязательным. Force не обходит gateway: получает Unsupported до factory/HTTP. Это предварительное решение о dispatch, не игнорирование отказа уже выполненного compact и не его подмена generation.

Порог остаётся локальным ориентиром: его достижение не блокирует generation из-за Unsupported compact. При unknown window запрос с полным рабочим контекстом передаётся после явной server-policy проверки; при известном окне прежний guard может отклонить его до HTTP. Серверный отказ возвращается без обрезания истории, retry, смены модели/ключа/коннектора или повторного инструмента. Режим best-effort compact с возможной потерей сжатой части не включён.

## Конкретный сценарий T05

Например, turns1–10 содержат ограничения задачи и результаты инструментов. Compact возвращает opaque compaction item, writer принимает окно через turn10. Следующая generation содержит это окно и turn11; turns1–10 остаются в истории AgentBridge, но уже не дублируются в рабочем input. Если upstream отклоняет encrypted compact, existing recovery может удалить весь compaction item и вернуть успех только по turn11. При нескольких output items теряется соответствующая сжатая часть, при единственном opaque item — всё покрытое окно. Нарушается пригодность принятого окна как замены покрытого prefix для следующей generation. Локальная сохранность истории, Completed compact и save-before-activation этого не предотвращают.

Это условный сценарий на конкретной ошибке, не доказанная несовместимость всех разных моделей и не утверждение о частоте на deployment. Compact-only/global mapping лишь допускает разные пути; response.model может быть requested echo. Independently verified actual identity не является самостоятельным условием включения, если существующий контракт подтверждает совместимость окна.

## Что требуется для включения

Минимальное текущее клиентское изменение — явно отключить автоматическую активацию неподтверждённого compact и продолжать полный контекст через guard; оно выполнено. Для последующего включения нужна проверка совместимости existing POST /v1/responses/compact с последующим POST /v1/responses для используемого маршрута/модельного pool, включая encrypted-error recovery. Проверка должна различать использование окна и успешный ответ после его удаления. Одного requested echo, успешной fixture либо пробы одного аккаунта недостаточно для всего pool. Новое server API, header/metadata, guessed flags, генерация вместо compact и доработка sub2api не требуются и не предлагаются.

[Проверки](results.md) используют actual AgentRunner/ContextCompactor/Sub2Api/HttpClientLibrary с fake handlers и in-memory storage: порог, полный canonical input/tool pair, unknown/known budget, HTTP rejection без retry, force, прежнее окно/непокрытый хвост. Это проверка отключённого режима, не compact transport acceptance. Actual compact lifecycle/terminal/writer integration не реализованы; Completed-only/save-before-activation и история прежних путей сохранены.03 не completed,04 не начат.
