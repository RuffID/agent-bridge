# 03.03. Сжатие рабочего контекста

Статус: **blocked** (T05 и незавершённые03.01–03.02). Зависимости: 03.02.

[Этап](main.md) · [Главный план](../main.md)

## Конкретный результат

Sub2Api CompactAsync совместим с existing ContextCompactor.

## Затрагиваемые части и объём

Sub2Api compact transport/reader, ContextCompactor и IDialogContextWriter existing path; Sub2Api tests.

Подключить подтверждённый compact endpoint выбранного sub2api-направления и корректный body. При отсутствии поддержки вернуть явный Unsupported; не имитировать compact обычной генерацией. Сохранить canonical compact items и metadata, Completed-only acceptance, save-before-activation, покрываемый terminal prefix и непокрытый хвост. Не урезать историю до лимита провайдера молча.

## Проверки

Completed/Failed/Canceled/malformed compact, capabilities unavailable, fresh expiry, late response, второй compact, tools на границе окна, отказ сохранения, непрозрачные items, timeout/disposal. Логи не называют compact принятым до успешного writer результата; ключи и содержимое не выводятся.

## Критерии готовности

Compact можно принять существующим портом без изменения вызывающего бизнес-кода. Неподдержанный compact остаётся явным ограничением и блокирует заявление полной поддержки обязательного сценария.

## Фактический результат

Подтверждён исходный route POST /v1/responses/compact и whitelist body; это не доказательство фактической модели. Сервер допускает compact-only mapping и Gateway.OpenAICompactModel fallback, а response model может быть переписан обратно в requested ID. Возможны SSE bridge/keepalive, поэтому Accept application/json не доказывает unary response. [Evidence и необходимый контракт](contract-blockers.md).

CompactAsync явно Unsupported до HTTP без замены обычной генерацией. ContextCompactor, IDialogContextWriter, canonical items/metadata, save-before-activation и история не менялись. Их прежняя семантика не объявляется новой Sub2Api acceptance. T05 остаётся открыт.

[Проверки](results.md): отказ без callback/HTTP и без изменения canonical input; codex-lb compact regression. Actual Sub2Api compact lifecycle/discriminator, Completed-only writer integration, второй compact/хвост и фактическая upstream модель остаются непроверенными до снятия блокировки.

В продолжении03 установлено, что обе forwarding ветки применяют compact/global model override уже до первого send. Серверное расширение отклонено; новые discriminator/metadata/enforcement не требуются от sub2api. [Клиентская адаптация](contract-blockers.md) должна использовать подтверждённый existing endpoint/body/terminal либо оставить Unsupported, не выдавая requested echo за actual model. Новое выполнение/проверка транспорта не добавлены, T05 открыт, existing Completed-only/save-before-activation/history path сохранён.
