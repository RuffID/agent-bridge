# 03.03.05. Сохранение и активация compact-окна

Статус: **not-started**. Зависимости:03.03.04 и сохраняющее силу положительное подтверждение03.03.02.

[Этап03](main.md) · [Навигатор compact](03.03-compaction.md)

## Конкретный результат

Подключить Sub2Api CompactAsync к existing ContextCompactor/IDialogContextWriter и принять окно только после подтверждённого Completed и успешного сохранения. Включение automatic compact допустимо только вместе с проверкой этих условий.

## Затрагиваемые части и объём

Sub2Api gateway, existing application compaction path и in-memory integration tests. Сохранить terminal prefix/ThroughTurnSequence, непокрытый хвост, original history, canonical items/encrypted reasoning, instructions/effort, ordering и tool pairs. Новые provenance, persistence schema и restart04 не добавлять; использовать прежние порты и бизнес-вызовы.

Не активировать Failed/Canceled/malformed, просроченный/поздний результат либо результат при отказе writer. Не подменять ошибку выполненного compact обычной generation и не повторять бизнес-инструменты. Лог принятия окна появляется только после успешного writer. Синхронизировать AGENTS изменённых областей.

## Проверки и критерии готовности

Actual gateway/compactor с fake HTTP и in-memory writer: Completed-only, save-before-activation, fresh expiry/late response, отказ сохранения, tools на границе, несколько output items, второй compact и следующий generation request из принятого окна + непокрытого хвоста. Проверить сохранность полной истории и отсутствие retry/replay.

Изолированные проверки доказывают клиентские инварианты; совместимость сервера опирается отдельно на03.03.02. При утрате этого основания сохранять режим03.03.01. Адресные сборки/tests — по ограничениям03.03.03.

## Фактический результат

Не реализован для Sub2Api compact. Регрессия existing core/CodexLb не заменяет эту интеграцию.
