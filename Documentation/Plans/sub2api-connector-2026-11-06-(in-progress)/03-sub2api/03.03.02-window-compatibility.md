# 03.03.02. Пригодность compact-окна для следующей generation

Статус: **blocked T05; статический анализ завершён, допуска compact нет**. Зависимости:03.03.01 и источники wire-контракта01.01.

[Этап03](main.md) · [Навигатор и сценарий потери prefix](03.03-compaction.md) · [T05](../open-questions.md)

## Конкретный результат

Установить по существующему контракту, может ли opaque output POST /v1/responses/compact заменить покрытый terminal prefix в последующем POST /v1/responses для рассматриваемого маршрута/model pool, включая invalid_encrypted_content recovery. Указать границы доказательства и конкретное основание допуска либо сохранения запрета.

## Объём и зависимости

Перечитать endpoint/body/output, compact/global mapping, forwarding и sanitizer; сверить current source с [описью](contract-source-evidence.json), сохранив evidence01–02. Владелец вывода — AgentBridge; sub2api и соседние библиотеки только читаются. Исходники, fixtures и сведения о deployment имеют разные границы достоверности.

Возможность mapping не доказывает несовместимость. Response.model может быть requested echo; independently verified actual identity не является отдельным условием. Принятый план Б не подтверждает использование opaque compact. Новые server API, headers, metadata или guessed flags не планируются.

## Проверки и критерии готовности

Положительное основание должно различать generation с использованием покрытой истории и успешный ответ после удаления окна; одной успешной fixture или одного аккаунта недостаточно для всего pool. При недостатке доказательств записать конкретный сценарий, нарушаемое требование и минимальное клиентское поведение; оставить03.03.03–03.03.05 не начатыми и безопасный режим03.03.01 включённым.

Этот подэтап не зависит от05.03 и не разрешает live-проверки. Если без отдельно разрешённой приёмки доказательства получить нельзя, T05 остаётся открытым; запуск этапа05 ради разблокировки03 не подразумевается.

## Фактический результат

На2026-11-07 существующий контракт **не даёт достаточного основания исключить успешную generation после удаления покрытого compact-окна** на рассматриваемом HTTP OpenAI-маршруте/model pool. Это отрицательный результат проверки достаточности контракта, а не доказательство несовместимости конкретного deployment или всех моделей. Анализ завершён; положительный gate T05 остаётся blocked.03.03.03–03.03.06 и04 не начинались.

### Проверенные условия маршрута

| Условие | Что установлено по source | Почему сценарий остаётся возможным |
| --- | --- | --- |
| POST /v1/responses/compact → POST /v1/responses | Оба пути обслуживает Responses handler; legacy compact передаёт requireCompact=true в scheduler, обычная generation — false | Фильтр возможности compact относится к отдельному запросу, не удостоверяет чтение возвращённого окна следующей generation. Unknown compact support также допускается; supported не означает совместимость opaque output со всем pool |
| HTTP/SSE клиента | Handler помечает HTTP ingress; resolveOpenAIWSDecisionByClientTransport принудительно выбирает http_sse | Включённый серверный WS сам по себе не переводит этот клиентский путь на иной recovery и не исключает рассматриваемую HTTP-ветку |
| Model mapping | Compact-only/global mapping может отличаться от generation; ordinary и passthrough применяют mapping по разным правилам | Это возможность разных upstream путей, не доказанная несовместимость. Отсутствие mapping либо одинаковая модель также не отключают encrypted-error recovery |
| Аккаунт и sticky session | Для каждого запроса выполняется selection; sticky допускает miss, исключение аккаунта, eligibility recheck и escape; handler допускает failover | Нет контрактной привязки compact→generation ко всей совместимой группе. Даже фиксированный аккаунт и отсутствие account switches не устраняют same-account recovery |
| Ordinary HTTP recovery | Первый HTTP400 с invalid_encrypted_content вызывает trimOpenAIEncryptedReasoningItems и повтор с изменённым body. Sanitizer удаляет весь encrypted compaction/compaction_summary item | Условие recovery не ограничено API-key аккаунтами, compact endpoint или сменой модели; ordinary OAuth HTTP-путь не получает отдельного исключения. Следующий успешный ответ обрабатывается обычным JSON/SSE reader без отказа из-за удаления окна |
| Passthrough | В собственной HTTP error-ветке passthrough именно этого invalid-encrypted удаления нет | Для этого узкого пути риск не доказан. Но нет свидетельства, что рассматриваемый deployment/pool всегда остаётся в нём; handler может перейти на ordinary account. Cross-mode sanitizer удаляет только encrypted reasoning, а не compaction: последующее удаление compaction происходит уже в ordinary recovery |
| Успешный ответ | После recovery выполняется обычная обработка результата; публичного подтверждения использования покрытого окна этот путь не формирует | Completed generation и response.model echo не различают использование окна и успешный ответ только по хвосту. Plan Б сохраняет клиентские данные, но не восстанавливает prefix в уже изменённом upstream input |

### Оставшийся сценарий и нарушаемое требование

1. Compact покрывает terminal turns1–10; принятое opaque окно заменяет их в рабочем input. [ContextBuilder](../../../../AgentBridge/Application/ContextBuilder.cs) добавляет active context и только turns после ThroughTurnSequence.
2. Следующий input — encrypted compaction item + turn11. Ordinary upstream отвечает HTTP400 invalid_encrypted_content. Для этого сценария не нужны client retry, смена модели или аккаунта.
3. Forward1139–1164 удаляет item через sanitizer426–441 и повторяет запрос к тому же аккаунту с одним хвостом. Если upstream возвращает пригодный terminal JSON/SSE, recovery не запрещает успешный исход. Полная история остаётся в AgentBridge, но turns1–10 уже отсутствуют у модели.

Нарушается существующее требование пригодности окна как замены покрытого terminal prefix: [OpenSpec delta, «Сжатие sub2api через общий сценарий», сценарий «Успешное сжатие»](../../../../openspec/changes/add-sub2api-connector/specs/agent-runtime/spec.md). Completed compact и успешное сохранение обеспечивают принятие результата, но не получение покрытого содержания следующей generation. Принятая canonical граница не разрешает best-effort потерю этой части.

[HTTP regression source](../../../../../sub2api/backend/internal/service/openai_gateway_service_hotpath_test.go), TestOpenAIGatewayService_Forward_HTTPRetryRecoveryDropsCompaction, использует один API-key account, compaction + message, первый400 и второй200; проверяет удаление compaction во второй отправке. Его синтетический usage-only ответ не является actual compact→generation приёмкой AgentBridge и не доказывает ошибку deployed OAuth pool. [Sanitizer regression source](../../../../../sub2api/backend/internal/service/openai_gateway_request_body_reasoning_test.go), TestTrimOpenAIEncryptedReasoningItems_Compaction, покрывает оба encrypted типа. Go tests только прочитаны, не запускались.

### Минимальная клиентская мера и предел вывода

**Не создавать и не активировать новое неподтверждённое compact-окно; продолжать полный PreparedRequest через отдельный generation budget guard. Эта мера уже реализована в03.03.01.** AutomaticCompactionEnabled=false, Disabled без compact/save и explicit/force Unsupported до factory/HTTP подтверждены текущим source; новые код/флаги/transport не нужны. Старое opaque состояние не получает новой гарантии совместимости; его provenance/restart остаются за пределами этой задачи.

Сверены51 effective source entry существующей описи: расхождений с локальным sub2api0.2.20 нет. Дополнительно прочитан и зафиксирован openai_client_transport.go. Source доказывает условное поведение recovery; пригодность deployment/pool и недостижимость ошибки не установлены. Одной успешной fixture, одного аккаунта, requested echo или независимо известной identity недостаточно, чтобы исключить этот путь для всего рассматриваемого pool. Новая independently verified identity сама по себе не требуется.

Нового клиентского решения нет. Допустимо сохранять03.03.01; переход к03.03.03 возможен только по отдельному поручению и при новом достаточном основании, исключающем описанную потерю для рассматриваемого пути. Это не требование нового API/headers/metadata/pool revision/single-attempt или доработки sub2api. Сборки, тесты, CLI OpenSpec и live/deployment проверки не выполнялись. Работа остановлена после03.03.02.
