# Обязанности и настройки приложения

Приложение определяет, кому и для каких задач доступен агент. AgentBridge выполняет согласованный сценарий в этих границах.

## Что предоставляет приложение

- Достоверную идентичность пользователя и проверку доступа к агенту, диалогу и бизнес-объектам.
- Инструкции агента, источники разрешённых сведений и обработчики инструментов с проверкой аргументов и текущих прав.
- Адрес сервера, ключи, выбранную модель и effort, подключения и жизненный цикл ресурсов.
- Интерфейс, который отличает предварительный текст, завершённый ответ, ошибку и неизвестный исход действия.
- Подготовку БД, расписание очистки, хранение и проверку резервных копий.
- Безопасное логирование: без ключей, подключений и полного содержимого диалога.

Например, регистрация инструмента «Отменить заказ» описывает доступную операцию. Она не даёт любому пользователю право отменить чужой заказ.

## Что можно настроить

Порог сжатия, запас входного бюджета, срок хранения, мягкий порог байтов и ограничения выполнения задаёт приложение. Библиотека проверяет допустимость значений. Подключение DLL и регистрация зависимостей не запускают операции автоматически.

| Параметр | Начальное значение |
| --- | --- |
| Срок хранения нового диалога | 7 дней |
| Мягкий порог содержимого | 10 МиБ |
| Порог сжатия | 32 000 токенов |
| Запас входного бюджета | 4 096 токенов |
| Максимум проходов сжатия за вызов сжатия | 3 |
| Максимум шагов с инструментами за обращение | 8 |
| Ожидание генерации и отдельно сжатия | По 180 секунд |
| Effort | medium, если доступен выбранной модели |

Это переопределяемые начальные значения, не обязательные правила для всех внедрений. Модель и provider БД выбираются явно. Срок хранения backup не имеет готового значения по умолчанию: приложение обязано его задать.

Пример: приложение может хранить новые диалоги 14 дней. Уже созданный диалог с прежним сроком останется под прежней датой истечения.

Количество одновременно выполняемых инструментов, число вызовов за шаг и их общий срок приложение задаёт отдельно. Отмена зависит от корректного поведения обработчиков: библиотека ожидает уже начатые операции, а не принудительно убивает их.
