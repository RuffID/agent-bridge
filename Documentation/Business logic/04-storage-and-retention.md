# Хранение, лимиты и удаление

## Выбор БД

Подключающее приложение выбирает SQLite или PostgreSQL и указывает параметры подключения в своей конфигурации. SQLite не является обязательным провайдером. Обе реализации используют EFCoreLibrary как основу доступа к данным.

Замена провайдера не меняет бизнес-сценарий общения с агентом. Перенос уже существующих данных между БД — отдельная операция, а не автоматическое следствие смены строки подключения.

## Данные диалога

Хранению подлежат история сообщений, состояние выполнения обращений, результаты инструментов и состояния рабочего контекста. Для сохранения непрерывности важны последовательность событий и связь с конкретным диалогом.

Хранилище не должно смешивать историю разных пользователей. Сохранение видимого текста ответа не заменяет сохранение необходимых элементов протокола модели.

## Ограничения

Объём считается на диалог в байтах сохраняемого содержимого: сообщения, результаты инструментов и состояния контекста. Для текстового и JSON-содержимого учитываются байты UTF-8 сохраняемой формы, для бинарного содержимого — фактические байты. Индексы, служебные страницы БД и другой overhead провайдера не входят в эту метрику.

Начальный порог — 10 МиБ (`10 485 760` байт). Это мягкий порог: его превышение возвращается приложению как предупреждение, но не удаляет историю и не блокирует диалог. Рабочий контекст продолжает сжиматься по токенному порогу. По превышению сохранённого объёма не запускается бесконечный compact, который не способен уменьшить архив истории.

Срок хранения задаётся конфигурацией и отсчитывается от создания диалога. Начальное значение конфигурации — 7 дней; приложение может указать другой срок. Логика истечения использует настроенный срок, а не захардкоженное число дней. Новое сообщение, смена модели и сжатие не продлевают этот срок. Сжатые состояния подчиняются политике хранения вместе с исходной историей.

## Время удаления для интерфейса

AgentBridge возвращает дату создания, срок истечения `ExpiresAtUtc`, признак истечения срока и текущий объём содержимого. `ExpiresAtUtc` вычисляется из даты создания и срока хранения, действовавшего при создании диалога. Изменение конфигурации задаёт срок новым диалогам.

Приложение может показать пользователю, когда диалог истечёт. Это время истечения доступности диалога; физическое удаление выполняется обслуживанием БД после наступления срока. Просроченный диалог не используется для нового обращения, даже если очередь очистки ещё не удалила строки.

## Удаление

История удаляется из БД обычными операциями удаления через EFCoreLibrary. В удаление входит согласованный набор зависимых данных: сообщения, связанные результаты инструментов, состояния контекста и другое сохраняемое содержимое диалога.

После удаления история не должна возвращаться из старого сжатого состояния или из результата запроса, который начался до удаления. Обработка диалога и очистка должны согласовывать изменения его состояния.

Автоматическая очистка удаляет истёкший диалог вместе с зависимыми состояниями. Превышение мягкого порога байтов не запускает частичное удаление истории. Отдельное явное удаление пользователем также учитывает связанные состояния и выполняющиеся обращения.

## Обслуживание

AgentBridge предоставляет операции проверки/обновления схемы и удаления истёкших диалогов. Подключающее приложение вызывает startup-обслуживание и запускает очистку по своему расписанию.

Очистка читает один ограниченный пакет истёкших диалогов и удаляет их последовательно через базовые read/delete операции EFCoreLibrary со сценарным сохранением. Равенство текущего времени сроку означает истечение. Каждый кандидат повторно проверяется перед удалением; выборка не является правом удалить новую жизнь того же ID. Settings диалога удаляются вместе с историей и контекстом.

Приложение явно вызывает `ExpiredDialogCleanup.CleanupAsync(limit, cancellationToken)` и определяет расписание. Отчёт различает подтверждённые удаления, ожидаемые отказы, неизвестные исходы и не начатые кандидаты. Partial/отмена не выдаются за успех; уже удалённые соседи не возвращаются после ошибки следующего кандидата. Внутри вызова нет бесконечной выборки или retry. Completed означает обработанный пакет, а не отсутствие других истёкших строк. [Фактический API22](<../Technical documentation/22-expired-dialog-cleanup.md>).

Для резервного копирования перед миграциями используется отдельный контракт обслуживания EFCoreLibrary; этап12 подключает его через явный API без автозапуска. Очистка диалогов не выполняет backup/restore.

Приложение явно выбирает первую установку либо обновление и обеспечивает SingleInitializer: другие экземпляры, запись и DDL остановлены на всё время обслуживания. Ошибки доступа не считаются отсутствующей БД. Миграции существующей БД с изменениями разрешаются только после подтверждённого backup; при отсутствии изменений копия не создаётся. Готовые backup автоматически не удаляются: их срок хранения и восстановление задаёт оператор. Удаление диалога из рабочей БД не удаляет его из старых копий.

BackupRetentionPeriod требует явного положительного срока приложения перед обслуживанием, без default. Проверка этой настройки не означает автоматическое удаление копий; retention исполняет приложение. Срок хранения backup не берётся из срока истечения диалогов. Подтверждение backup не является проверкой восстановления. [Фактический API и ограничения](<../Technical documentation/06-database-maintenance.md#подключение-agentbridge-этапа-12>).
