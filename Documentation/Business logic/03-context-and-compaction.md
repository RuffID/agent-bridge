# Контекст и сжатие

## Состав контекста

Рабочий контекст включает инструкции агента, необходимые данные приложения, сообщения диалога и состояние предыдущих шагов. К состоянию относятся также вызовы инструментов, их результаты и элементы протокола модели, необходимые для продолжения.

Полная история в БД и контекст текущего обращения имеют разные задачи. История хранит события диалога, рабочее окно содержит информацию для очередного запроса к модели.

## Порог сжатия

Сжатие запускается по числу токенов рабочего контекста. Порог задаётся в конфигурации подключающего приложения и может меняться без изменения исходного кода AgentBridge.

При проверке порога учитывается подготовленный запрос: инструкции, данные приложения, история или уже сжатое состояние, новое сообщение и необходимые описания инструментов. Количество сообщений или длина только последнего текста не заменяют размер всего рабочего контекста.

Порог сжатия отличается от мягкого порога объёма данных в БД. Сжатие может уменьшить очередной запрос, сохранив прежний объём истории. Начальный порог рабочего контекста — 32 000 токенов; размер определяется соответствующим модели tokenizer с отдельным учётом непрозрачного состояния.

## Результат сжатия

Для одного диалога могут последовательно появляться несколько состояний контекста. Новое состояние связано с диалогом и указывает, какую часть истории оно представляет. Следующее обращение использует актуальное состояние и сообщения, появившиеся после него.

Покрытие на уровне обращений представляет только последовательный префикс с конечными статусами. Ноль означает, что обращения ещё не покрыты. Выполняющееся обращение не считается полностью покрытым: у него ещё могут появиться ответы модели и результаты инструментов. Незавершённое обращение внутри префикса также запрещает такое покрытие. Это согласованная граница доменных метаданных; точная граница отдельных протокольных событий и сборка следующего контекста реализуются вместе с Responses/composition/compact на последующих этапах.

Сжатый контекст может содержать непрозрачное состояние модели. AgentBridge сохраняет его в пригодном для повторного использования виде. Преобразование всего результата в одну текстовую сводку не является универсальным контрактом.

Сжатие само по себе не удаляет исходную историю. Удалением управляет [политика хранения](04-storage-and-retention.md).

## Повторное сжатие

Долгий диалог может сжиматься повторно по мере накопления контекста. Само число предыдущих сжатий не заставляет библиотеку удалить диалог или автоматически создать новый.

В одном обращении повторение ограничено: начальное значение — до 3 последовательных проходов. Повторное сжатие прекращается, если целевой размер достигнут или размер больше не уменьшается. Библиотека возвращает состояние контекста, чтобы приложение могло предложить пользователю начать новый диалог.

Продолжение разрешено, пока рабочее окно можно отправить выбранной модели. Фактическое превышение допустимого входного бюджета — отдельная явная ошибка, а не повод бесконечно вызывать compact.

## Неполное сжатие и сбои

До успешного получения и сохранения нового состояния прежний контекст остаётся актуальным. Ошибка сжатия не должна приводить к потере истории или замене её пустой сводкой.

Сжатие не гарантирует сохранение каждой детали. Поиск по старым сообщениям в текущем объёме проекта отсутствует.

Источник требований: [agent-runtime](../../openspec/specs/agent-runtime/spec.md).
