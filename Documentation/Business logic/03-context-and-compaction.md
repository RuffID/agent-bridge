# Контекст, история и сжатие

История — сохранённые события диалога. Контекст — сведения, которые передаются модели для очередного ответа. Они не обязаны совпадать по объёму.

В запрос входят инструкции агента, разрешённые данные приложения, актуальное состояние разговора, последующие сообщения и новый вопрос. Описания инструментов и результаты их работы тоже занимают место. Короткий вопрос не гарантирует короткий запрос.

## Зачем нужно сжатие

Когда запрос достигает настроенного порога, библиотека может получить от модели более компактное состояние завершённой части разговора. Новое состояние используется только после успешного сохранения. Текущее незавершённое обращение и новые сведения не считаются уже покрытой историей.

Сжатие не удаляет исходную историю и не продлевает срок диалога. Оно не гарантирует сохранение каждой детали; поиск по старым сообщениям для возвращения утраченной детали не предусмотрен.

Пример: вместо длинного обсуждения заказа модель получает сжатое состояние и новые сообщения после него. Если важной детали в рабочем контексте больше нет, нельзя обещать, что модель сама найдёт её в архиве.

## Ограничения размера

Токены — единицы, которыми оценивается объём запроса модели. Встроенный счётчик поддерживает определённый набор точных имён моделей. Наличие модели в каталоге сервера ещё не означает поддержку её счётчиком.

Часть состояния может быть непрозрачной: библиотека умеет сохранить её, но не знает её полный размер. Это относится также к некоторым файлам, изображениям и неизвестным элементам. Известный размер текста не подменяет полную оценку; default RequireLocalEstimate блокирует отправку. Приложение может явно выбрать ServerValidation: известная часть с резервом проверяется локально, неизвестную часть проверяет сервер, полная оценка остаётся неизвестной.

## Если сжать не удалось

Число последовательных проходов сжатия ограничено настройками. При известном размере увеличившийся или не уменьшившийся вариант не принимается. При ошибке остаётся последнее успешно сохранённое состояние.

Допустимое непрозрачное состояние может быть сохранено с отметкой «полный размер неизвестен». Default guard требует обоснованную полную оценку; explicit ServerValidation разрешает передать неизвестную часть на серверную проверку. Ручное сжатие доступно ниже автоматического порога без обхода проверки доступа, срока и сохранения. Ошибка второго прохода не отменяет уже сохранённый первый.

Приложение может объяснить ограничение и предложить новый диалог. Автоматического удаления истории ради бюджета нет.
