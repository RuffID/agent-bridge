# Контекст и сжатие

## Состав контекста

Рабочий контекст включает инструкции агента, необходимые данные приложения, сообщения диалога и состояние предыдущих шагов. К состоянию относятся также вызовы инструментов, их результаты и элементы протокола модели, необходимые для продолжения.

Полная история в БД и контекст текущего обращения имеют разные задачи. История хранит события диалога, рабочее окно содержит информацию для очередного запроса к модели.

Этап16 реализует подготовку полного запроса: инструкции агента остаются отдельным системным полем, вход объединяется в порядке разрешённых источников приложения, актуального окна, полного хвоста последующих обращений и ещё не сохранённого нового сообщения/результата инструмента. Описания разрешённых инструментов и параметры включаются в тот же подготовленный запрос для будущего подсчёта. Источники выбирает приложение; они проверяют права и сохраняют любые заданные canonical роли без автоматического повышения. Сбой источника не заменяется пустым контекстом, вызовы последовательны и соблюдают отмену.

Полные известные пары вызова функции и результата сохраняются, в том числе через границы окна и новых элементов. Если известный вызов ещё не имеет результата, включая частичные arguments после обрыва, подготовка явно отказывает до готового запроса. История/частичный ответ остаются целыми; выдуманных результатов нет. Повторный call_id в разных полных парах допустим. Непрозрачное состояние не раскрывается ради проверки скрытых вызовов. Envelope и metadata продолжения не являются сообщениями, output отдельных model steps повторно не включается, если уже сохранён в Items. [Фактический API](<../Technical documentation/16-context-composition.md>).

## Порог сжатия

Сжатие запускается по числу токенов рабочего контекста. Порог задаётся в конфигурации подключающего приложения и может меняться без изменения исходного кода AgentBridge.

При проверке порога учитывается подготовленный запрос: инструкции, данные приложения, история или уже сжатое состояние, новое сообщение и необходимые описания инструментов. Количество сообщений или длина только последнего текста не заменяют размер всего рабочего контекста.

Порог сжатия отличается от мягкого порога объёма данных в БД. Сжатие может уменьшить очередной запрос, сохранив прежний объём истории. Начальный порог рабочего контекста — 32 000 токенов; размер определяется соответствующим модели tokenizer с отдельным учётом непрозрачного состояния.

## Результат сжатия

Этап17 реализует offline токенизацию всего подготовленного запроса и явный guard входного бюджета. Полные инструкции, история, новое сообщение, schemas инструментов, calls/results и входные параметры учитываются вместе. Проверенные exact model IDs ограничены первичным mapping; другая модель явно Unsupported, без подстановки tokenizer. Точный локальный BPE видимого payload отличается от оценки полного input и серверного billing count.

У встроенного offline counter изображение/файл, opaque reasoning/compaction, неизвестное содержимое или скрытый server state продолжения дают известные токены текста отдельно, но полная оценка неизвестна. Настроенный резерв не заменяет эту оценку: guard отказывает и не объявляет отправку допустимой. При известной оценке guard проверяет её с резервом против input_context_window; равенство допустимо по оценке, достижение порога при estimate>=TokenThreshold возвращается отдельно. Например, короткое сообщение с длинными schemas может превысить бюджет. Независимый порт сохраняет возможность обоснованной полной оценки приложения, отдельный источник её на17 не реализован. Проверка вызывается приложением явно, не обрезает историю и не запускает compact. [API/примеры/границы17](<../Technical documentation/07-tokenizer-and-settings.md#public-guard-и-подключение>).

Для одного диалога могут последовательно появляться несколько состояний контекста. Новое состояние связано с диалогом и указывает, какую часть истории оно представляет. Следующее обращение использует актуальное состояние и сообщения, появившиеся после него.

Покрытие на уровне обращений представляет только последовательный префикс с конечными статусами. Ноль означает, что обращения ещё не покрыты. Выполняющееся обращение не считается полностью покрытым: у него ещё могут появиться ответы модели и результаты инструментов. InProgress внутри префикса также запрещает такое покрытие. Terminal Incomplete/Failed/Canceled являются конечными статусами, но не успешным ходом модели. Сборка16 берёт Items активного окна и все Items turns после префикса; никакого item cutoff внутри текущего обращения нет. Этап18 сжимает только активное окно и следующий непрерывный terminal prefix. Вклад приложения, InProgress и последующие обращения, новый несохранённый input остаются отдельно; они учитываются в полном бюджете и не дублируются при следующей композиции.

Сжатый контекст может содержать непрозрачное состояние модели. AgentBridge сохраняет его в пригодном для повторного использования виде. Преобразование всего результата в одну текстовую сводку не является универсальным контрактом.

Сжатие само по себе не удаляет исходную историю. Удалением управляет [политика хранения](04-storage-and-retention.md).

## Повторное сжатие

На этапе18 вклады источников фиксируются один раз на вызов. Успешно сохранённое окно становится актуальным; ошибка второго прохода оставляет окно первого. Неполный/ошибочный результат, пустой кандидат при непустой истории, устаревшая версия или истечение срока не заменяют принятое окно. Время проверяется заново после ожидания модели и подсчёта перед записью, срок не продлевается.

По решению пользователя валидный непрозрачный результат сохраняется даже при неизвестной полной оценке: возвращается UnknownBudget и дальнейшее сжатие останавливается. Это не разрешает генерацию: отдельный guard требует обоснованную оценку полного нового запроса. Прошлый usage не используется как бюджет нового запроса. При известном размере кандидат, не уменьшающий запрос, не принимается. Любой другой результат остановки также требует отдельной проверки полного бюджета. [API18](<../Technical documentation/18-context-compaction.md>).

Долгий диалог может сжиматься повторно по мере накопления контекста. Само число предыдущих сжатий не заставляет библиотеку удалить диалог или автоматически создать новый.

В одном обращении повторение ограничено: начальное значение — до 3 последовательных проходов. Повторное сжатие прекращается, если целевой размер достигнут или размер больше не уменьшается. Библиотека возвращает состояние контекста, чтобы приложение могло предложить пользователю начать новый диалог.

Продолжение разрешено, пока рабочее окно можно отправить выбранной модели. Фактическое превышение допустимого входного бюджета — отдельная явная ошибка, а не повод бесконечно вызывать compact.

## Неполное сжатие и сбои

До успешного получения и сохранения нового состояния прежний контекст остаётся актуальным. Ошибка сжатия не должна приводить к потере истории или замене её пустой сводкой.

Сжатие не гарантирует сохранение каждой детали. Поиск по старым сообщениям в текущем объёме проекта отсутствует.

Источник требований: [agent-runtime](../../openspec/specs/agent-runtime/spec.md).
