# Создание диалога и обработка обращения

Диалог объединяет историю одного владельца. Обращение — один новый запрос внутри этого диалога; для ответа могут понадобиться несколько обращений к модели и инструментам.

## Создание

Приложение проверяет пользователя и его доступ к выбранному агенту, затем создаёт диалог с отдельным идентификатором. При создании фиксируются владелец, время создания и срок истечения.

Новый диалог не удаляет старый и не переносит его историю автоматически. Если приложение пытается создать уже существующий идентификатор, оно получает отказ, а не замену прежних данных.

## Обработка сообщения

1. AgentBridge читает диалог и проверяет владельца, срок и состояние.
2. Фиксирует модель, effort, доступ и ограничения для этого обращения.
3. Получает разрешённые сведения приложения и собирает контекст с новым сообщением.
4. Проверяет размер запроса; при необходимости выполняет ограниченное сжатие и снова проверяет полный бюджет.
5. Отправляет запрос модели. Если модель запрашивает инструмент, выполняется проверка прав и допустимости действия.
6. Сохраняет полученные результаты и, при необходимости, продолжает разговор с моделью.
7. Возвращает приложению итог и отдельно сообщает, подтверждено ли его сохранение.

Пример: «Что с заказом?» может потребовать чтения статуса заказа, а затем второго запроса модели для понятного ответа. Следующий вопрос «Когда доставка?» использует доступный контекст того же диалога.

## Что видит пользователь

При потоковом ответе текст появляется постепенно. Эти фрагменты предварительны: поток может оборваться, а сохранение — завершиться отказом. Успешный итог требует подтверждённого завершения модели и сохранения обращения.

Повторно переданный идентификатор уже существующего обращения не запускает его заново. Приложение должно различать новый вопрос и повтор отправки после сбоя; новый идентификатор сам по себе не делает повтор бизнес-действия безопасным.
