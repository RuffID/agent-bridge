# Сценарные write UoW

- DialogCatalogCreationUnitOfWork фиксирует root/immutable scope/profile/policy/empty index/feed одной transaction. DialogCatalogStaging вызывается внутри canonical writes до commit; ошибка projector отменяет весь write, не требует callback после runner. Все queries/staging идут через EFCoreLibrary base API.
- DialogLifecycleUnitOfWork выполняет atomic Begin/input/settings/lease, renew, Finalize, fence и append-only recovery. Registered root legacy writes запрещены; LoadRunAsync требует exact live lease/epoch либо явную internal catalogControl границу. Старая LoadAsync/constructor ABI сохраняется только для legacy semantics.
- Lease deadline выдаёт TimeProvider; expired lease остаётся Active до fence. ExpiredLease проверяет persisted deadline; ConfirmedQuiescence требует trusted host verifier. Fence повышает epoch, но не устанавливает исход handler и не переписывает original terminal. Поздний writer отклоняется даже с совпавшим root token.
- Recovery требует quiescence, full bounded pending batch и CAS incarnation/root/recovery revision/epoch. NotStarted доказывается журналом; Started после финализации — Unknown. Explicit unknown acknowledgement или отдельный trusted evidence принимаются append-only без replay/успеха из client payload. Evidence I/O выполняется после preflight вне transaction; итог повторно проверяет CAS/epoch. Same operation ID/payload возвращает durable result без повтор verifier; altered payload — Conflict.
- Compact хранит RecoveryRevision и отказывается скрыть pending. Delete/expiry требуют освобождённую lease, stage tombstone/feed атомарно с root removal; terminal/settings/recovery не создают message metadata. Только exact catalog/clock/recovery CAS/PK collision классифицируется Conflict; unknown commit/read/finalize exceptions не превращаются в Ready и требуют fresh scope/authoritative lookup.

- DialogSettingsUnitOfWork21 сохраняет только отдельную строку выбора через base CRUD. Guard проверяет original root token/owner/incarnation/expiry, Settings.Version — independent CAS. Ни revision истории, ни active snapshot не refresh/retry. UnitOfWorkScope распознаёт только exact settings DbUpdateConcurrency/PK collision; FK/driver/serialization/commit errors остаются исключениями. External catalog/compatibility вызывается до scope.
- BeginWithSettingsAsync атомарно сохраняет turn snapshot; legacy Begin допускает null. Terminal update читает прежний SettingsJson parent-aware и не теряет его. SaveWithModelAsync сохраняет selected compact provenance; standalone SaveAsync оставляет null. Settings/provenance metadata не входят в ContentBytes.

- DialogToolAttemptUnitOfWork реализует отдельный IDialogToolAttemptWriter через existing scope/guard/Domain/base CRUD. Start добавляет одну позицию только к Completed сохранённому step InProgress turn. Outcomes меняют Started либо фиксируют pre-action отказ/NotStarted, confirmed outputs добавляются той же transaction. Root revision и размер журнала изменяются атомарно; повтор позиции/terminal outcome запрещён. Никаких handlers/I/O/automatic retries внутри scope.

- `DialogCreationUnitOfWork`, `DialogTurnUnitOfWork`, `DialogContextUnitOfWork`, `DialogDeletionUnitOfWork` реализуют существующие узкие Application write ports. Общего контейнера всех репозиториев нет; read ports не зависят от UoW.
- `UnitOfWorkScope` владеет begin/save/commit/rollback/dispose и cleanup. `EfUnitOfWorkSession` использует только `IUnitOfWorkContext<AgentBridgeContextKey>` текущей EFCoreLibrary. Transaction Serializable; retry strategies, ambient/enlisted/existing transaction отклоняются. Операции не повторяются автоматически.
- Один scoped `PersistenceOperationGate` применяется и к read ports, и к write scope. Параллельные/вложенные операции отклоняются до доступа к контексту. Приложение не должно использовать зарегистрированные infrastructure/base repositories напрямую или держать tracked state между операциями. Внешние модель/инструменты и их ожидание не передаются в technical callbacks.
- После begin root загружается tracking с исходными concurrency values. Guard проверяет ID, owner ordinal, текущий nullable expiry из scoped политики/CreatedAtUtc по явному NowUtc, incarnation/revision. Domain валидирует полную историю и мутацию. Cleanup повторно проверяет текущую политику внутри transaction; null запрещает автоматическое удаление. Все child writes сопровождаются root revision update. Legacy expiry column не переписывается; исходный token не refresh.
- `TurnContentStaging` сохраняет новые items и reports раздельно, с parent-aware step ID и последовательностями. StoredContentSize считает UTF-8 фактически сохраняемых текстовых колонок, включая полные отчёты и прежние compact. Prefix не удаляет данные и не определяет cutoff items.
- Только подтверждённый root `DbUpdateConcurrencyException` из save превращается в Conflict. При создании отдельно распознаётся PK_Dialogs collision: SQLite PRIMARYKEY1555 либо PostgreSQL23505/Dialogs/PK_Dialogs; driver-specific проверка делегируется явно подключённым IAgentBridgeDatabaseProvider. Общий UoW не зависит от driver assemblies. DI передаёт модули в новый конструктор; прежний двухаргументный конструктор сохраняет бинарную сигнатуру, но самостоятельный scope без модулей не классифицирует PK. Остальные driver/serialization/constraint ошибки не маскируются. Commit/cleanup errors всегда исключения; первичная и вторичные ошибки сохраняются.
- Cleanup выполняется после любой начатой собственной transaction и до возврата результата. Неизвестные begin/commit/cleanup блокируют gate до уничтожения DI scope. Если begin не передал transaction, чужой tracker/transaction не очищаются.
- Реальные relational atomicity/locking/cascades здесь не подтверждены: tests используют fake boundaries и настоящую EF metadata без подключения. Migrations, SQL, БД, hosting, network и внешние процессы не запускать.
