# Интеграционные проверки PostgreSQL

- Реальные проверки помечены Dependency=Database; обычный изолированный набор исключает этот trait. Компиляция не разрешает запуск PostgreSQL, Docker, pg_dump/pg_restore или SQL.
- DatabaseIntegrationCollection выполняется непараллельно. Один ленивый Testcontainers.PostgreSql postgres:18 принадлежит fixture; случайный loopback-порт, пользователь/БД abverify_, bounded tmpfs без внешних volumes. Fsync/full_page_writes/synchronous_commit включены. Failed startup не повторяется и не превращается в Skip.
- Каждый case владеет отдельной БД, приватным temp-каталогом и backup. Источник подключения — только созданный fixture контейнер. Внешние/рабочие БД, чужие контейнеры/volumes и изменение Docker Desktop запрещены. Cleanup ожидается независимо от отмены runner, ошибки удаления не скрываются; чужие ресурсы и Docker prune запрещены.
- Windows runner и реальные pg_dump/pg_restore major18 проверяются PostgreSqlIntegrationTools. Explicit AGENTBRIDGE_PG_DUMP/AGENTBRIDGE_PG_RESTORE имеют приоритет; неверный override не вызывает fallback. Выбор путей и process runner не подменяются Docker exec.
- Данные проходят actual public ports, EFCoreLibrary CRUD и короткие UoW. Технический SQL теста идёт через IDatabaseCommands. Backup/restore использует штатный provider/process runner и отдельную тестовую БД; сверяются схема, history и payload. Down выполняется IMigrator библиотечного context facade.
- Runner/cleanup/settings/recovery tests сохраняют проверку atomic rollback, отдельного committed Started до handler, CAS/guards/late delete, fixed expiry, no replay, journal/provenance и historical rows при Down/Up. Local HTTP handlers не выполняют реальную сеть; gates и созданные задачи освобождаются и await в finally.
- Схема содержит только PostgreSQL migration IDs из IntegrationSchemaExpectations; SQLite/SQL Server fixtures удалены. Миграции и snapshot не регенерируются ради тестов.
- Restore/build требуют GeneratePackageOnBuild=false. Изолированный запуск при отдельном поручении: dotnet test --project <csproj> --filter-not-trait 'Dependency=Database'. Реальный PostgreSQL-набор: --filter-trait 'Dependency=Database' при применимом разрешении запуска. Недоступные prerequisites дают ошибку, не Skip.
