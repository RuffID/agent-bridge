# Изолированные проверки композиции sub2api

- xUnit v3/Microsoft.Testing.Platform, actual public Integration DI и options. SQL Server module используется только для disconnected graph/metadata; нет подключения, host, SQL, Docker, live HTTP/OAuth или процессов из тестов.
- ValidateScopes и ValidateOnBuild включены. HTTP factory и scoped key source наблюдаются отдельно от регистрации; fake overrides проверяются как identity, их методы не имитируют успех приложения.
- Catalog/Generation fixtures собирают existing composition/actual HttpClientLibrary со scoped source и fake handlers/local streams. Unknown-window mode проверяет declared manifest без budget/provenance guesses. Generation tests проверяют полный request, JSON/SSE и non-stream fallback, terminal/partial/tools/awaited callbacks, caller/deadline/primary+cleanup и safe outcome logs. Continuation/compact отказывают до factory. Canonical гарантия относится к границе AgentBridge; upstream сохранность/identity не выдаются за подтверждённые.
- Ordinary catalog подтверждает exact ID; manifest нового режима только объявляет exact ID/effort/API-доступность. Оба не доказывают input budget/runtime pool. Synthetic catalog/settings cases не являются evidence сервера.
- Sub2ApiAutomaticCompactionTests связывает actual AgentRunner/ContextCompactor/gateway/HttpClientLibrary с in-memory storage: Disabled без compact dispatch/save выше threshold, полный input с reasoning/tool pair, known/unknown budget, server rejection без retry, force Unsupported и прежнее окно/хвост. Это не проверка server compact или restart04. Default automatic compact прежних реализаций проверяется existing core/CodexLb regression.
- JsonElement откладывает декодирование: проверять invalid UTF-8 также в неизвестном поле. Cancellation/deadline fixtures должны достичь требуемой send/body стадии; незавершённый поток не должен объявлять Content-Length=0. Подготовить DI до отсчёта deadline, дождаться и освободить все gated задачи. Combined cleanup failures должны остаться наблюдаемыми.
- Legacy surface checks сравнивают текущие DLL с embedded текстовым Fixtures/legacy-api-baseline.json. Профиль пользователя, внешний kit, artifacts поставки и папки плана для этого не нужны. Эталон получен из проверенных старых DLL; не обновлять expected по новым исходникам ради зелёного теста.
- Provenance cases вызывают actual gateway/runner/standalone compactor без автоматической маркировки fixture: отказ до factory/Begin, родное окно с чужим tail, неизвестный новый input и binding mismatch. Protocol fixtures задают synthetic marker вручную; output provenance не заменяет canonical/continuation и не отправляется upstream. Тесты JSON DTO не доказывают restart на БД.
- Сохранность внешнего kit/frozen binaries и совпадение текстового эталона со старыми PE отдельно проверяет Delivery/LegacyBaseline с явным AgentBridgeLegacyBaselineRoot. Сравнение API не заменяет resolution неперекомпилированных consumers против нового delivery closure, runtime и live приёмку.
- Restore/build с GeneratePackageOnBuild=false; тестовый runner только после compile-check с тем же BaseOutputPath. Отсутствующий embedded resource является ошибкой, silent Skip и автоматического восстановления нет.
