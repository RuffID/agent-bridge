# Generic Host integration tests

- Настоящий `HostBuilder`, public `AddAgentBridge`, actual AgentRunner, reader/query/gate, CodexLb/HttpClientLibrary и DI scopes. `Microsoft.Extensions.Hosting` остаётся только в тестовом проекте; production-код не изменять.
- Пользователь разрешил запуск Generic Host внутри тестового процесса. Нет production приложения/сервера, live HTTP, БД или Docker. `NoDatabaseInterceptor` запрещает попытку подключения; provider metadata/UoW resolution не доказывают SQL и транзакции.
- Existing base repository doubles подключаются через linked Compile, не копируются. Они дают синтетический read snapshot настоящему reader; UoW, facade, runner и gateway не подменять. Сценарий runner останавливается при чтении каталога либо при read failure до durable begin; generation/checkpoints/recovery на БД здесь не проверены.
- `HostingWorker` принадлежит тестовому приложению: связывает stopping token, создаёт async scope, ожидает сценарий и сохраняет primary/scope cleanup errors. AgentBridge сам не запускает worker и не связывает операции с host lifetime. Стандартный BackgroundService.StopAsync не гарантирует распространения ошибки ExecuteTask; проверка ошибки StopAsync относится к явной политике приложения, причины проверять на actual runner/pipeline.
- Отдельные gates координируют вход HTTP, transport cancellation, возврат операции и async disposal; без задержек/retries/Skip/opt-in. Все ожидания bounded. Finally освобождает gates, отменяет/ожидает работу, вызывает StopAsync и DisposeAsync с независимым cleanup budget; неожиданные cleanup errors распространяются.
- Borrowed HttpClient/handler/logger принадлежат приложению. Ответы/body принадлежат actual HTTP pipeline. Проверять HTTP cleanup errors в `Exception.Data["HttpClientLibrary.CleanupExceptions"]` и identity первичной причины; raw errors не являются безопасным UI/log контрактом.
- Проверки используют текущие xUnit v3/Microsoft.Testing.Platform: `dotnet test --project tests/AgentBridge.Hosting.Tests/AgentBridge.Hosting.Tests.csproj`. Restore/build требуют `-p:GeneratePackageOnBuild=false`; no-build запускать только после успешного build того же BaseOutputPath.
