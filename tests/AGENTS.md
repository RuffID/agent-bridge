# Изолированные тесты

## Карта и зависимости

- `AgentBridge.Tests` проверяет ядро/Application и ссылается только на корневой production-проект.
- `AgentBridge.CodexLb.Tests` проверяет транспортный адаптер и ссылается на `AgentBridge.CodexLb`.
- `AgentBridge.Persistence.EfCore.Tests` проверяет адаптацию хранения и ссылается на `AgentBridge.Persistence.EfCore`.
- Тестовые зависимости: xUnit, Microsoft.NET.Test.Sdk и runner Visual Studio. Production-проекты не ссылаются на тесты, а корневой compile glob исключает весь каталог `tests`.
- Проверки конфигурации используют Microsoft.Extensions.Configuration с in-memory источником и обычный ServiceProvider. Публичная граница — групповые DI-расширения, options и явный `IStartupValidator`, без хоста. Секреты в fixtures только синтетические.
- ModelSelectionTests проверяет точные ID/effort, неизвестные budgets, границы/переполнение и независимость snapshots. ModelCatalogTests проходит публичный DI-путь AddCodexLbModelCatalog/IModelSettingsReader с actual HttpClientLibrary и fake HttpMessageHandler/local streams: приоритет/null/ошибки ключей, обновление каталога, malformed shape, 64 КиБ, освобождение, секреты в raw state/сообщениях и caller cancellation. Fake IModelCatalog отдельно проверяет сохранение того же ServiceError при поздней отмене и отклонение успешного snapshot после отмены; реальные HTTP/upstream не доказаны.
- Проверки диагностики ядра используют публичные `AddAgentBridgeDiagnostics`/`BeginOperation`, собирающий ILoggerProvider и Serilog provider приложения с sink в памяти. Serilog `4.3.0` и Serilog.Extensions.Logging `10.0.0` — только тестовые зависимости; production использует Microsoft.Extensions.Logging `10.0.3` и не выбирает Serilog-конфигурацию.
- `DialogTests` проверяет публичный доменный API с явным UTC: владение, фиксированный срок, terminal statuses, версии, удаление и устаревшие операции. Не использовать reflection/friend assemblies для создания состояния; данные создаются через доменные фабрики. Покрытие контекста — только terminal prefix, включая 0; restart и concurrency хранилища эти тесты не доказывают.
- `ApplicationPortsTests` проверяет lifecycle/отмену, независимость JSON/коллекций, per-call доступ, полный envelope и отделение metadata от input-items. Однопоточные fake ports демонстрируют выражение owner/expiry/incarnation/revision guards и round-trip, но не доказывают реальную атомарность, persistence или restart. Из ядра не подключать инфраструктурные сборки ради этих тестов.
- Persistence-тесты проверяют EF metadata SQLite/PostgreSQL (без соединения), локальные composite keys/FK/cascades, fixed-field/concurrency metadata, UTC ticks, полный JSON/lifecycle и точный scoped adapter/base repository API EFCoreLibrary. DTO serialization не является restart на БД; ограничения и атомарность БД не подтверждены. Не использовать SQLite in-memory/EF InMemory. Restore/build/test этих проектов требуют `-p:GeneratePackageOnBuild=false`, чтобы ProjectReference не запускал упаковку EFCoreLibrary.
- Persistence-проект также ссылается на обе provider migrations assemblies. ProviderDesignTimeTests вызывают настоящие factories, сравнивают модель с runtime DI и проверяют сборку, collation, ticks, guards и собственные таблицы. Generated snapshot/designer target models и текущая relational model сравниваются через IMigrationsModelDiffer без SQL, UpOperations/DownOperations, connection или host; это согласованность артефактов, не relational enforcement на БД.
- Base repository fakes проверяют настоящие сигнатуры CRUD/predicate/include, parent filters, sequence/version ordering и mapping полного read path. Staging хранится отдельно от исходных строк, не имитирует commit. Управляемые interleavings проверяют повторное чтение root при удалении/пересоздании/смене revision; это не EF provider/concurrency тесты. Заглушки не должны маскировать orphan children пустой историей.
- `DialogRestorationTests` проверяет валидирующее восстановление и append Domain. `DialogWritePortsTests`/`UnitOfWorkScopeTests` используют раздельные committed/staged копии и fake transaction: guards, partial failures, root CAS interleavings, token/recreate, prefix/history, commit/cleanup uncertainty и gate. Это проверки production координации, не доказательство SQL isolation. `PersistenceRegistrationTests.BaseUpdatePreservesOriginalConcurrencyAndFixedFields` проверяет actual EFCoreLibrary Update + EF tracker metadata без SaveChanges/connection.
- `DatabaseMaintenanceRegistrationTests` проверяет actual options/provider registrations, capabilities, scoped connection metadata и общий gate без открытия соединения. `DatabaseMaintenanceTests` вызывает настоящий библиотечный coordinator по AgentBridgeContextKey с fake provider/migration boundaries: порядок, receipt, target, cancellation/deadline, failures/collision и poison. Backup/native/process/DB/restore не выполняются; fake collision подтверждает остановку coordinator, а не filesystem enforcement. Все созданные test tasks должны быть отменены либо await до выхода.
- Проверять структуру state и отформатированный текст, отсутствие переданного Exception, сохранение провайдеров/фильтров/фабрики и владения logger, caller/deadline по раздельным исходным токенам. Не переносить секретные fixtures в scopes или enrichers приложения.

## Правила проверки

- Проверять значимое поведение и ошибки по мере реализации этапов. Не добавлять фиктивные тесты для пустых сборок или проверки констант проекта.
- Compile-check не запускает приложение или тесты. Обычный runner `dotnet test`/xUnit разрешён для изолированных unit-тестов без реальных интеграций; технический процесс тестового runner не считается запуском приложения.
- Не запускать приложение или библиотеку через hosting, TestServer, WebApplicationFactory и аналогичные механизмы. Такие проверки не относятся к изолированным unit-тестам.
- Использовать подставные порты, ответы и локальные потоки. Не обращаться к реальному HTTP, БД, SQL, Docker или внешним процессам; SQLite in-memory также не относится к проверкам без БД.
- Новые тесты размещать здесь, а не рядом с production-кодом; инфраструктура тестов не становится публичным API библиотеки.
- XML `<summary>` тестовых типов и методов писать на русском. Реализации интерфейсов в test doubles документировать `<inheritdoc/>`.
- Перед restore/build/test проверять конкретный `.csproj` и действующие build-файлы. Указывать точную команду, фактический результат и пропуски; успешную сборку не выдавать за пройденные тесты.
