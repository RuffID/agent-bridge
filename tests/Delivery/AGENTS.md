# Проверка поставки DLL

- BoundedHistoryRegistration.cs — PostgreSQL compile-only actual B03 sample: explicit policy/IBoundedDialogReader/RunBoundedAsync. Не исполнять методы и не объявлять source-linked compile доказательством полного kit. Новый kit проверять через external binary consumer без ProjectReference, exact/RID/lock guards и fresh hashes; scripts требуют отдельного разрешения пользователя текущей задачи.

- Для одного multi-RID dll-nuget bundle собственные DLL/XML всех RID обязаны совпадать по SHA256. Fresh SDK Builds используют отдельный ArtifactsPath каждого variant, общий ArtifactsPivots=release и PathMap=<absolute variant build root>=/_/delivery-build как в Prepare-DeliveryTests.ps1. Иначе CodeView/generated source paths меняют hashes; исправлять build inputs, не копировать DLL между kits и не ослаблять mixed guard.

- Assemble-NuGetDelivery.ps1 создаёт из проверенных стандартных SDK-комплектов одного провайдера schema3 dll-nuget: ровно 11 собственных DLL с доступными XML, включая AgentBridge.Sub2Api из closure Integration, переносимые References и exact PackageReference для прямых зависимостей всех локальных библиотек. Ожидаемый состав проверяется по именам; число выводится из того же списка. Остальные зависимости/native/resources разрешает NuGet приложения. Local DLL всех RID должны совпадать; mixed/hash/case/path failures отклоняются до создания destination. Скрипт запускается только после разрешения точной команды и не запускает DLL или restore.
- AgentBridge.NuGetDelivery.props импортируется после app PackageReference: одинаковая версия приводится к exact, отличающаяся/повторная отклоняется Error-only validation. net10.0, явный поддержанный RID и packages.lock.json обязательны; все поддержанные RID включаются в restore. Существующий lock включает locked mode; изменение зависимостей требует явного обновления lock. Central package management не поддерживается этой поставкой. NuGetDeliveryTests сверяет local closure и обязательные package roots с исходным SDK graph без загрузки DLL.
- Assemble-SharedDelivery.ps1 запускается только по разрешению точной команды, после fresh standard kits. Проверяет полный input manifest/size/hash/case/provenance до destination; одинаковые nonnative assets всех/части RID сохраняются в common/common variants один раз, native остаются по RID. Schema2 manifests и explicit generated variant props выбирают ровно runtime closure платформы; source deps/manifest — evidence. SharedDeliveryTests проверяет новый layout/dedup/source closure/paths/PE/ELF без исполнения DLL.
- После разделения EF-провайдеров каждый kit содержит общий адаптер, выбранный AgentBridge.Persistence.<Provider> и ровно одну migrations assembly. Соседние провайдеры отсутствуют. Source compile-only samples требуют app-owned явную регистрацию модуля до facade; Все примеры используют PostgreSQL.

- Consumer/SimpleRegistration.cs и UsageRegistration.cs используют actual AddAgentBridge facade14. App ILoggerFactory и owned HttpClient обязательны; individual source регистрируется до facade, business callbacks scoped. Source linked compile в isolated persistence tests не является external binary kits15/16; old kits24 не содержат Integration DLL. Delivery graph/матрица обновляются в15/16.

- `Compatibility/` — внешний binary test consumer для PostgreSQL net10.0/EF 10.0.14/Npgsql 10.0.3. Копировать исходники вне всех repo и импортировать новый dll-nuget kit после прямых PackageReference. Граф включает EF Design/Tools/InMemory и Serilog; InMemory не используется как БД. Строгий DI, закрытый PostgreSQL connection, tracker, offline BPE и Sub2Api JSON/SSE через HTTP stub проверяют фактические DLL без SQL/сети/host. Linux варианты только compile/metadata; тестовое исполнение разрешено только на текущем Windows RID.

- Consumer/StrictConfigurationRegistration.cs — compile-only пример explicit limits/source modes Audit Remediation13, linked isolated persistence tests. Методы не исполняются; source compilation не доказывает external binary kits15/16 или runtime18.


- `Build/` — служебный SDK library project общей runtime closure Integration facade + выбранной migrations assembly. Собственная DLL не поставляется. Явный `DeliveryProvider=PostgreSql` и `RuntimeIdentifier=win-x64|linux-x64|linux-arm64` проверяются Error-only target; перед каждым вариантом обязателен restore, сборки последовательны с отдельными output. Только обычный Build, без Exec/executable hooks, pack/publish и запуска.
- `Build/Assemble-Delivery.ps1` по отдельному разрешению либо действующему прямому разрешению тестовых скриптов читает fresh SDK deps/assets/output и package originals. Генерирует новый kit/variant props/manifest с hashes/provenance; destination не переиспользуется. Совпадающие SDK aliases разрешены лишь по kind/hash; conflicting/missing/RID/architecture failures не маскируются. Native assets не удалять ради минимального provider kit. Generated outputs — только ignored artifacts. Упаковщики вызывает только явно запущенный Prepare-DeliveryTests.ps1; сборка Metadata, решения или delivery library не запускает scripts.
- `-Configuration Debug|Release` отражает actual input build в manifest (default Debug для прежних потребителей). Передавать явно при Release-поставке; SDK deps evidence входит в manifest и переносится вместе с комплектом.
- `Consumer/` — compile-only библиотека net10.0 с явным RID и actual configuration/facade примерами. Импорт через AgentBridgeDeliveryRoot: полный бинарный kit или собственные DLL с NuGet requirements; без source ProjectReference. Копировать .cs/.csproj и комплект вне всех repo. Методы не исполнять; app factories/авторизация/business source остаются обязанностью приложения. Матрица — PostgreSQL win-x64/linux-x64/linux-arm64; не расширять evidence на Linux existing providers.
- `AgentBridge.Delivery.props` рядом с `lib/`, `native/<RID>/`, `resources/<culture>/` и generated `AgentBridge.Delivery.variant.props`; переносимые paths/case. SDK-selected managed/XML/native/resources копируются стандартными items. Satellites сохраняют culture-relative paths, не включаются в прямые root References и проверяются по SDK/package SHA/culture/PE. Error-only target отклоняет несовпадающий app RID. Не смешивать версии/комплекты/RID. Delivery deps — resolution evidence, приложение создаёт собственный deps.
- `Metadata/` — отдельный явно запускаемый проект чтения PE/ELF/XML/manifest и Roslyn symbols без загрузки/исполнения AgentBridge/native/DI/HTTP/БД. В solution только File item, а не Project. MSBuild передаёт фиксированный проектный artifacts/delivery-tests через AssemblyMetadata; cwd и BaseOutputPath не меняют выбор поставки. Assembly fixture требует ready.json и удерживает общую read-блокировку подготовки до окончания тестов. Missing kit — явная ошибка, не Skip. Проверять managed closure/versions/resources/API/XML, native PE/ELF, exact case/hash/SDK entries и negative controls. Cross-build не runtime evidence.
- `Build/Prepare-DeliveryTests.ps1` — build-only подготовка трёх PostgreSQL Release SDK variants, одного DLL/NuGet bundle и PostgreSQL shared bundle. Последовательные restore/build используют отдельные ArtifactsPath всех проектов каждого variant. Упаковщики не изменяются и получают fresh destinations в собственном staging. SHA256 содержимого/путей исходников, build inputs и SDK позволяет повторной сборке использовать готовые комплекты; изменение входов удаляет ready до работы. Источники повторно проверяются перед заменой current. Exclusive lock запрещает конкурирующую подготовку и замену во время тестов; очистка ограничена собственным artifacts/delivery-tests. Ошибка не активирует предыдущий комплект; failed staging сохраняется для диагностики. Git-команды не выполняются, provenance содержит working-tree hashes.
- Подготовка поставки выполняется отдельной явной командой до Metadata; автоматического BeforeCompile/Exec нет. Build только компилирует тесты, --no-build читает последнюю явно подготовленную поставку. AgentBridgeSkipDeliveryPreparation больше не требуется. Scripts требуют разрешения точной команды по общим правилам. Команды и ограничения — README.md этой папки.
- `LegacyBaseline/` — отдельный read-only audit historical kit/frozen DLL и происхождения embedded API-эталона. В solution только File items. AgentBridgeLegacyBaselineRoot задаётся явно при сборке; default профиля, поиск, восстановление и silent Skip запрещены. Обычные Sub2Api tests используют только embedded текстовый эталон. Full old→new ABI этим не доказывается.
- `Abi/` — отдельная статическая old→new проверка всех TypeRef/MemberRef/MethodSpec frozen consumers и semantic API новой closure. Frozen SQL Server consumers относятся к удалённому контракту и не проверяются как совместимые; semantic surface ядра/Integration/CodexLb проверяется отдельно. Явные baseline/current roots, pinned hashes и fail-fast для неизвестных metadata; target DLL не исполняются. В solution только File items; обычная сборка не требует external baseline.
- `Runtime/` — отдельный test consumer и явный helper для hash-gated managed/native loading, facade/scopes/app ILogger/offline BPE. Собирается вне repo только из binary kit; native Load/Free не доказывает provider операции. Без HTTP/БД/hosting; границы и обязательный preflight — в Runtime/AGENTS.md. Linux runtime требует своей actual машины.
- Во всей build chain передавать `-p:GeneratePackageOnBuild=false`. Generated DLL/XML/deps/assets/manifest не редактировать вручную и не добавлять в Git. Не заявлять runtime/native validation по результату compile/metadata checks.
