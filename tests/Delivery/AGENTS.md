# Проверка поставки DLL

- Assemble-NuGetDelivery.ps1 создаёт из проверенных стандартных SDK-комплектов одного провайдера schema3 dll-nuget: только 10 собственных DLL/XML, переносимые References и exact PackageReference для прямых зависимостей всех локальных библиотек. Остальные зависимости/native/resources разрешает NuGet приложения. Local DLL всех RID должны совпадать; mixed/hash/case/path failures отклоняются до создания destination. Скрипт запускается только после разрешения точной команды и не запускает DLL или restore.
- AgentBridge.NuGetDelivery.props импортируется после app PackageReference: одинаковая версия приводится к exact, отличающаяся/повторная отклоняется Error-only validation. net10.0, явный поддержанный RID и packages.lock.json обязательны; все поддержанные RID включаются в restore. Существующий lock включает locked mode; изменение зависимостей требует явного обновления lock. Central package management не поддерживается этой поставкой. NuGetDeliveryTests сверяет local closure и обязательные package roots с исходным SDK graph без загрузки DLL.
- Assemble-SharedDelivery.ps1 запускается только по разрешению точной команды, после fresh standard kits. Проверяет полный input manifest/size/hash/case/provenance до destination; одинаковые nonnative assets всех/части RID сохраняются в common/common variants один раз, native остаются по RID. Schema2 manifests и explicit generated variant props выбирают ровно runtime closure платформы; source deps/manifest — evidence. SharedDeliveryTests проверяет новый layout/dedup/source closure/paths/PE/ELF без исполнения DLL.
- После разделения EF-провайдеров каждый kit содержит общий адаптер, выбранный AgentBridge.Persistence.<Provider> и ровно одну migrations assembly. Соседние провайдеры отсутствуют; SqlServer ARM64 kit может не иметь native assets. Source compile-only samples требуют app-owned явную регистрацию модуля до facade; SqlServerRegistration исключается из external non-SqlServer consumer.

- Consumer/SimpleRegistration.cs и UsageRegistration.cs используют actual AddAgentBridge facade14. App ILoggerFactory и owned HttpClient обязательны; individual source регистрируется до facade, business callbacks scoped. Source linked compile в isolated persistence tests не является external binary kits15/16; old kits24 не содержат Integration DLL. Delivery graph/матрица обновляются в15/16.

- Consumer/StrictConfigurationRegistration.cs — compile-only пример explicit limits/source modes Audit Remediation13, linked isolated persistence tests. Методы не исполняются; source compilation не доказывает external binary kits15/16 или runtime18.

- Consumer/SqlServerRegistration.cs — текущий compile-only пример persistence/maintenance API SQL Server: source компилируется как linked item isolated persistence tests, методы не исполняются. Это не новый DLL kit и не бинарная проверка MSSQL; комплекты трёх RID и внешний consumer относятся к Audit Remediation15/16.

- `Build/` — служебный SDK library project общей runtime closure Integration facade + выбранной migrations assembly. Собственная DLL не поставляется. Явные `DeliveryProvider=SqlServer|Sqlite|PostgreSql` и `RuntimeIdentifier=win-x64|linux-x64|linux-arm64` проверяются Error-only target; перед каждым вариантом обязателен restore, сборки последовательны с отдельными output. Только обычный Build, без Exec/executable hooks, pack/publish и запуска.
- `Build/Assemble-Delivery.ps1` по отдельному разрешению либо действующему прямому разрешению тестовых скриптов читает fresh SDK deps/assets/output и package originals. Генерирует новый kit/variant props/manifest с hashes/provenance; destination не переиспользуется. Совпадающие SDK aliases разрешены лишь по kind/hash; conflicting/missing/RID/architecture failures не маскируются. Native assets не удалять ради минимального provider kit. Generated outputs — только ignored artifacts. Только сборка Metadata вызывает упаковщики через Prepare-DeliveryTests.ps1; самостоятельный Build delivery library их не запускает.
- `-Configuration Debug|Release` отражает actual input build в manifest (default Debug для прежних потребителей). Передавать явно при Release-поставке; SDK deps evidence входит в manifest и переносится вместе с комплектом.
- `Consumer/` — compile-only библиотека net10.0 с явным RID и actual configuration/facade примерами. Импорт через AgentBridgeDeliveryRoot: полный бинарный kit или собственные DLL с NuGet requirements; без source ProjectReference. Копировать .cs/.csproj и комплект вне всех repo. Методы не исполнять; app factories/авторизация/business source остаются обязанностью приложения. Матрица — SQL Server три RID и SQLite/PostgreSQL win-x64; не расширять evidence на Linux existing providers.
- `AgentBridge.Delivery.props` рядом с `lib/`, `native/<RID>/`, `resources/<culture>/` и generated `AgentBridge.Delivery.variant.props`; переносимые paths/case. SDK-selected managed/XML/native/resources копируются стандартными items. Satellites сохраняют culture-relative paths, не включаются в прямые root References и проверяются по SDK/package SHA/culture/PE. Error-only target отклоняет несовпадающий app RID. Не смешивать версии/комплекты/RID. Delivery deps — resolution evidence, приложение создаёт собственный deps.
- `Metadata/` — isolated tests чтения PE/ELF/XML/manifest и Roslyn symbols без загрузки/исполнения AgentBridge/native/DI/HTTP/БД. Три прежние AGENTBRIDGE_*_DELIVERY_ROOT не читаются. MSBuild передаёт фиксированный проектный artifacts/delivery-tests через AssemblyMetadata; пути одинаковы для MTP CLI и Visual Studio adapter, не зависят от cwd или BaseOutputPath. Assembly fixture требует ready.json и удерживает общую read-блокировку подготовки до завершения тестов. Проверять managed closure/versions/resources/API/XML, native PE AMD64 либо ELF64 little-endian x86-64/AArch64, exact case/hash/SDK entries и mixed/wrong/missing negative controls. Cross-build не runtime evidence.
- `Build/Prepare-DeliveryTests.ps1` — build-only подготовка пяти Release SDK variants, трёх DLL/NuGet bundles и SQL Server shared bundle. Последовательные restore/build используют отдельные ArtifactsPath всех проектов каждого variant. Упаковщики не изменяются и получают fresh destinations в собственном staging. SHA256 содержимого/путей исходников, build inputs и SDK позволяет повторной сборке использовать готовые комплекты; изменение входов удаляет ready до работы. Источники повторно проверяются перед заменой current. Exclusive lock запрещает конкурирующую подготовку и замену во время тестов; очистка ограничена собственным artifacts/delivery-tests. Ошибка не активирует предыдущий комплект; failed staging сохраняется для диагностики. Git-команды не выполняются, provenance содержит working-tree hashes.
- Подготовка вызывается BeforeCompile только обычной сборки Metadata, DesignTimeBuild исключён. DisableFastUpToDateCheck заставляет Visual Studio выполнить MSBuild и проверить входы перед run при включённой сборке тестов. `--no-build` использует последнюю успешную подготовку. `AgentBridgeSkipDeliveryPreparation=true` предназначен только для compile-check без скриптов; это не проверка свежести поставки. Добавленный Exec/его первый проверочный запуск требуют отдельного разрешения точной команды по общим правилам. Команды и ограничения — README.md этой папки.
- `Runtime/` — отдельный test consumer и явный helper для hash-gated managed/native loading, facade/scopes/app ILogger/offline BPE. Собирается вне repo только из binary kit; native Load/Free не доказывает provider операции. Без HTTP/БД/hosting; границы и обязательный preflight — в Runtime/AGENTS.md. Linux runtime требует своей actual машины.
- Во всей build chain передавать `-p:GeneratePackageOnBuild=false`. Generated DLL/XML/deps/assets/manifest не редактировать вручную и не добавлять в Git. Не заявлять runtime/native validation по результату compile/metadata checks.
