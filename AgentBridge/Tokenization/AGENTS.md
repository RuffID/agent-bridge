# Offline tokenization

- ContextTokenCounter также реализует IContextContentInspector через тот же canonical shape parser, без BPE/model mapping. Это только opaque/unknown classification, не input estimate. Текстовая совместимость не зависит от поддержки exact model tokenizer; CountAsync неизвестной модели без явного оценочного режима по-прежнему Unsupported. DI registration сохраняет отдельные custom counter/inspector.

- Здесь реализация IContextTokenCounter через Microsoft.ML.Tokenizers2.0.0 и embedded O200kBase/Cl100kBase словари. Runtime network/download отсутствует. Подтверждённый mapping конечный, exact/ordinal: builtin IDs плюс явные TokenizationOptions.ModelEncodings приложения; библиотечный model resolver/prefix fallback не применять. Дополнительную кодировку подтверждает приложение, builtin конфликт запрещён; доступность/effort/window отдельно подтверждает catalog.
- Optional UnknownModelEstimateEncoding явно включает приблизительный BPE для ID без подтверждённого mapping; default null оставляет Unsupported. Count.IsApproximateEncoding=true не подтверждает словарь модели, KnownTokens также приблизителен, а opaque/continuation по-прежнему дают null full estimate. Mapping имеет приоритет; scalar encoding проверяется тем же validator и фиксируется при создании singleton. Guard/compactor допускают такой count только с explicit ServerValidation; модель/effort/input window остаются catalog-backed.
- ContextTokenCounter сохраняет parameterless constructor для builtin mapping и принимает IOptions<TokenizationOptions> для дополнений. Options.Validate и прямой constructor используют один safe validator; counter копирует словарь с StringComparer.Ordinal при создании и не читает изменяемые options между подсчётами. Работающий singleton не меняет mapping по reload, новый конфиг применяется после перезапуска. IContextContentInspector по-прежнему определяет форму без model lookup/BPE.
- Точный gpt-5.5 добавлен для existing Telegram default: существование подтверждено official model docs и local codex-lb registry; encoding — official tiktoken main gpt-5 family rule (2026-10-08). Runtime prefix matching по-прежнему запрещён, arbitrary suffix и gpt-5.4 не добавлены. Каталог/effort/input window проверяются отдельно.
- Точный gpt-5.6-sol добавлен 2026-10-09 для выбранной пользователем модели Telegram: encoding o200k_base подтверждается тем же official tiktoken gpt-5 family rule, ID присутствует в local codex-lb catalog. Другой регистр и произвольные suffix не получают confirmed mapping; доступность модели подтверждает live каталог, а не offline mapping.
- Точные gpt-5.6-terra и gpt-5.6-luna используют то же подтверждённое gpt-5 family rule. GPT-6/6.1 не объявляются подтверждёнными builtin кодировками; явный оценочный режим поддерживает их без угадывания exact mapping.
- KnownTokens считает известные payload, не billing. JSON framing — только локальная оценка полного известного input. Opaque/multimodal/unknown fields или continuation state => estimate null, известный текст сохраняется. Не токенизировать IDs/base64/encrypted content как скрытый input.
- Reserve/threshold принадлежат Application.ContextBudgetGuard, не BPE tokenizer. Counter/guard не меняют историю, не вызывают compact/HTTP/DB. Не вводить opaque estimates без согласования.
- Literal special-token markers являются обычным пользовательским текстом, не protocol special tokens. Изолированные проверки public counter/guard/DI — tests/AgentBridge.Tests/ContextTokenCounterTests.cs и ContextBudgetGuardTests.cs.
